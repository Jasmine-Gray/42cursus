# ワードウルフ MVPゲーム仕様

> ステータス: Draft 0.2
>
> 最終更新: 2026-08-18
>
> モック画面（[mock/](../../mock/)）とAPI契約（[spec/api/](../api/README.md)）に合わせた外部仕様。
> 通信の正確なフィールド定義は [openapi.yaml](../api/openapi.yaml) と [asyncapi.yaml](../api/asyncapi.yaml) を正とする。

## 1. ゲーム概要

似ているが異なる2つのお題を使うリアルタイム正体隠匿ゲーム。多数派（市民）と少数派（ワードウルフ）に
別々のお題が秘密で配られ、全員が自分のお題を前提に議論したあと、ワードウルフだと思う人物へ投票する。

世界観は探偵テーマ（捜査会議など）だが、ルールは標準的なワードウルフとする。
MVPでは質問回数や質問ラウンドを管理せず、制限時間内の自由チャットで議論する。

## 2. 用語

| 用語 | 定義 |
|---|---|
| 部屋 | プレイヤーと観戦者が集まり、同じメンバーで再戦できる場所 |
| ゲーム | 部屋の中で開始から結果確定まで行う1回の対戦 |
| プレイヤー | ゲームへ役職付きで参加するユーザー |
| 観戦者 | ゲームを閲覧するが、発言権と投票権を持たないユーザー |
| 多数派のお題 | 市民に配られるお題 |
| 少数派のお題 | ワードウルフに配られるお題 |

## 3. プレイ人数と役職

- プレイヤーは3〜8人とする。
- 役職はゲーム開始ごとにランダムに再抽選する。
- 同一ユーザーが複数のプレイヤーとして参加することはできない。

| 役職 | 人数 | 目的 |
|---|---:|---|
| 市民 | 3〜7人 | ワードウルフを投票で特定する |
| ワードウルフ | 1人 | 正体を隠して投票を回避する |

## 4. 秘密情報

- 各プレイヤーには自分のお題（1つ）とジャンルだけが配られる。
- **自分が多数派か少数派か（役職）は、本人にも結果確定まで知らされない。**
- 他プレイヤーのお題と役職は結果確定まで公開しない。
- お題ペアは部屋設定のジャンルとお題の近さ（わかりやすい/標準/むずかしい）に従いサーバーが選ぶ。

## 5. フェーズ

```text
LOBBY
-> DEALING
-> DISCUSSION（5分）
-> VOTING（30秒）
-> RESULT（結果表示30秒）
-> LOBBY
```

### 5.1 `LOBBY`

- ユーザーはプレイヤーまたは観戦者として部屋に参加する。
- 部屋を作成したユーザーが最初のホストになる。
- プレイヤーは準備状態を切り替えられる。
- プレイヤーが3〜8人で全員準備完了の場合、ホストがゲームを開始できる。
- ホストが退出した場合、参加日時が最も古いプレイヤーへホストを移譲する。

### 5.2 `DEALING`

- サーバーが役職とお題ペア（多数派用・少数派用）を決定する。
- 各プレイヤーへ本人用のお題だけを配る。
- 配布完了後、自動的に `DISCUSSION` へ進む。
- 画面上の開始カウントダウン（3秒）はクライアント演出であり、独立フェーズにしない。

### 5.3 `DISCUSSION`

- 制限時間は5分とする。
- 全プレイヤーが自由にチャットできる。
- 質問者、質問回数、回答順は制限しない。
- 時間終了後、自動的に `VOTING` へ進む。

### 5.4 `VOTING`

- 制限時間は30秒とする。
- チャットは閲覧のみとなる。
- 各プレイヤーはワードウルフだと思うプレイヤーを1人だけ選んで投票する。
- 自分自身には投票できない。
- 投票送信後の変更はできない。
- 投票先と得票数は結果発表まで公開せず、投票済み人数だけを全員へ配信する。
- 全プレイヤーの投票を受理した時点、または制限時間終了時に `RESULT` へ進む。

### 5.5 `RESULT`

- 勝者、全員の役職、両方のお題、各プレイヤーの得票数を公開する。
- 30秒間表示した後、全員を同じ部屋の `LOBBY` へ戻す。
- **`RESULT` から直接次のゲームを開始する遷移（再戦ショートカット）は存在しない。**
- 続けて遊ぶ場合は、ロビーで設定の確認・変更と準備完了をやり直し、ホストが改めて開始する。

## 6. 勝利条件

| 条件 | 勝者 |
|---|---|
| 最多得票がワードウルフだった | 市民（`WOLF_IDENTIFIED`） |
| 最多得票がワードウルフ以外だった | ワードウルフ（`WOLF_ESCAPED`） |

- 制限時間終了時は、受理済みの投票だけで集計する。
- 市民側の勝利は、ワードウルフが単独で最多得票となった場合のみとする。
- 最多得票が同数の場合、および投票が0件の場合はワードウルフ側の勝利とする。
- ゲーム中止は勝敗および戦績に含めない。

## 7. チャット

- `DISCUSSION` 中のプレイヤーだけが送信できる。
- 観戦者は閲覧のみとする。
- 1メッセージは前後の空白を除いた1〜300文字とする。
- プレーンテキストだけを扱い、HTMLとして解釈しない。
- 送信頻度は1秒に1件、かつ10秒間に5件までとする。
- 編集、削除、画像、ファイル添付、不適切表現の自動判定はMVPに含めない。
- 制限違反時は接続を切らず、対象メッセージだけを拒否する。

## 8. 観戦

- 観戦者は参加者、公開チャット、現在フェーズ、残り時間、投票済み人数をリアルタイムで閲覧できる。
- ゲーム進行中の役職と各プレイヤーのお題は閲覧できない。
- `RESULT` ではプレイヤーと同時に全役職とお題を閲覧できる。
- 観戦者の切断はゲーム進行へ影響しない。
- 観戦者が次のゲームへ参加する場合は、一度 `LOBBY` へ戻ってプレイヤー枠へ参加する。

## 9. 切断と再接続

### ロビー

- プレイヤーが退出した場合、そのプレイヤーを部屋から除外する。
- 退出者がホストならホストを移譲する。

### ゲーム進行中

- `DEALING`、`DISCUSSION`、`VOTING` 中にプレイヤーが切断した場合、ゲームとフェーズタイマーを最大20秒停止する。
- 20秒以内に全切断者が再接続した場合、同じ役職、お題、フェーズ、残り時間から再開する。
- 最初の切断から20秒以内に復帰しないプレイヤーがいる場合、ゲームを勝敗なしで中止して `LOBBY` へ戻す。
- 切断待機中に別のプレイヤーが切断しても待機期限を延長しない。

### 結果表示中

- `RESULT` 中の切断ではゲームを停止しない（結果は確定済み）。
- 切断者も30秒経過後は、ほかの参加者と同様に `LOBBY` へ戻った扱いとする。

## 10. 複数タブ

- 1ユーザーにつき、1部屋で有効なゲーム接続は1つとする。
- 新しい接続を有効とし、古い接続を無効にする。
- 古い接続からのゲーム操作は拒否する。

## 11. MVP対象外

- ワードウルフ2人以上の構成
- 複数ラウンドの投票と決選投票
- ウルフによるお題当て（逆転勝利）
- 結果画面からの再戦ショートカット（次のゲームは必ずロビーの開始フローを経由する）
- チャットの編集、削除、添付、モデレーション
- 部屋ごとの議論時間変更

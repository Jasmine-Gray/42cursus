## 1. プロジェクト概要

- Common Core 最終課題。**チームプロジェクト（4〜5人）**。
- **作るものは自由**（旧版のようなPong固定ではない）。チームでアイデアを出し、要件を満たすWebアプリを作る。
- 構成は2部：
  - **Mandatory part（必須部分）** — 全メンバーが必ず貢献する固定のコア要件
  - **Modules（モジュール）** — 選択制。合計 **14ポイント以上** で完成

### プロジェクト例（Subject記載）
- トーナメント付きマルチプレイヤーPong
- リアルタイム機能付きコラボプラットフォーム
- SNS、マッチメイキング付きオンラインゲーム（チェス等）
- プロジェクト管理アプリ、その他要件を満たす創造的なWebアプリ

## 3. Mandatory Part

### 3.1 一般要件（違反するとプロジェクト却下）
- **フロントエンド + バックエンド + データベース** を持つWebアプリであること
- **Git** を使用し、以下を満たすこと：
  - 全メンバーのコミットがある
  - 変更内容が分かる明確なコミットメッセージ
  - チーム内で適切な作業分担が見えること
- **コンテナ（Docker/Podman等）でデプロイし、1コマンドで起動**できること
- 最新安定版 **Google Chrome** で動作すること
- ブラウザコンソールに **警告・エラーが出ない** こと
- **プライバシーポリシー・利用規約ページ**（必須、評価で確認される）：
  - フッターリンク等からすぐアクセスできる
  - プロジェクトに即した中身のある内容（プレースホルダ・空ページは不可 → **却下**）
- **マルチユーザー同時利用サポート（必須）**：
  - 複数ユーザーの同時ログイン・同時操作
  - 同時アクションの適切なハンドリング
  - 該当する場合、リアルタイム更新が全接続ユーザーに反映される
  - データ破損・レースコンディションが起きないこと

### 3.2 技術要件
- 全デバイスで **明快・レスポンシブ・アクセシブル** なフロントエンド
- **CSSフレームワーク／スタイリングソリューション** を使用（Tailwind, Bootstrap, Material-UI等、自由選択）
- 認証情報は **Gitに含めない `.env`** に置き、**`.env.example` を提供**
- DBは **明確なスキーマとリレーション** を持つこと
- **基本的なユーザー管理システム**（必須）：
  - 最低限：**メール + パスワード認証**（パスワードはハッシュ化＋ソルト等、適切なセキュリティ）
  - OAuth・2FA等の追加認証はモジュールとして実装可
- **全フォーム・入力をフロントとバックの両方でバリデーション**
- ブラウザ・スクリプト・外部APIなど **バックエンドへの接続はすべてHTTPS**（コンテナ内部のバックエンド同士は非暗号化可）

### 「フレームワーク」の定義（Subject内）
構造化されたアーキテクチャ＋組み込み機能＋エコシステムを持つもの。
- フロント例: React, Vue, Angular, Svelte, Next.js（Reactはこの文脈ではフレームワーク扱い）
- バック例: Express, Fastify, NestJS, Django, Flask, Rails
- 非該当: jQuery, Lodash, Axios（ライブラリ）

## 4. モジュール（14ポイント必要）

- **Major = 2pt / Minor = 1pt**、合計 **14pt** で完成。
- 評価で不合格になるモジュールに備え、**14pt超を狙うのが推奨**。
- **評価時に各モジュールのデモを求められる。完全に動作するもののみ加点**（未完成 = 0pt）。

### 依存関係の注意
- **ゲーム系モジュール**（AI対戦, トーナメント, カスタマイズ, 観戦, 3人以上, 2つ目のゲーム）は **先にゲームを1つ実装していることが前提**
- ゲーム統計モジュールもゲーム実装が前提
- 高度なチャットは「User interaction」モジュールの基本チャットが前提
- **SSRとICPブロックチェーンバックエンドは非互換**

## 5. README.md 要件（評価対象・英語必須）

リポジトリルートに配置。以下を必ず含む：

1. **1行目**（イタリック）: *This project has been created as part of the 42 curriculum by \<login1\>[, \<login2\>...].*
2. **Description** — プロジェクト名、目的、概要、主要機能
3. **Instructions** — 前提条件（ソフト、バージョン、.env設定等）と実行手順（ステップバイステップ）
4. **Resources** — 参考資料 + **AIの利用方法の説明**（どのタスク・どの部分に使ったか明記）

### この課題で追加必須のセクション
- **Team Information** — 各メンバーのロールと責務
- **Project Management** — 作業の組織化方法、使用ツール、連絡チャネル
- **Technical Stack** — フロント/バック/DB/その他技術と選定理由
- **Database Schema** — DB構造の図または説明、テーブルとリレーション、主要フィールド
- **Features List** — 実装機能一覧、担当者、各機能の説明
- **Modules** — 選択モジュール一覧、ポイント計算、**各選択の正当化**、実装方法、担当者
- **Individual Contributions** — 各メンバーの貢献内訳、担当した機能・モジュール、直面した課題と解決

> 不十分なREADMEは評価に悪影響。明確・完全・誠実に書くこと。

## 8. AI利用ルール（Chapter I）

- AIは反復作業の削減・生産性向上に使ってよい
- ただし**生成物を完全に理解し、責任を持てるものだけ使う**
- 生成物は必ず自分で検証・レビュー・テストし、ピアレビューも受ける
- 評価で説明できないコードを使うと**プロジェクト失格**
- READMEのResourcesセクションに**AIをどう使ったか記載必須**

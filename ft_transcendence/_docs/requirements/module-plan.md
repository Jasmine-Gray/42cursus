## 2. 追加候補（余裕がある場合）

ゲーム本体の進捗と独立に進められるもの、または実装対象とほぼ重なるものを優先する。
**確定構成は15ptでマージンが1ptしかない**ため、下表の「最優先」2件（ORM / ゲーム統計）は
追加実装がほぼ不要な上積み枠として、採否を先に決めておく。

| モジュール | pt | 理由 |
|---|---|---|
| **最優先** ORM (Minor) | 1 | Ecto採用済み（decisions.md §2）。**実質取得済み。追加実装ほぼ不要** |
| **最優先** ゲーム統計・対戦履歴 (Minor) | 1 | 戦績・対戦履歴はAPI（`GET /users/me`、`GET /users/me/games`）とDB設計に含まれている。**実装対象と重複しており安い** |
| 高度なチャット (Minor) | 1 | 履歴永続化（chat_messages）とフレンドのゲーム招待ボタンはモック・DB設計に既にある。ブロック・既読/入力中が追加分 |
| 2FA (Minor) | 1 | ゲームと独立して作れる保険枠 |
| OAuth 2.0 (Minor) | 1 | 同上。42アカウントログイン等 |
| ゲームカスタマイズ (Minor) | 1 | 現MVP設定はジャンル・お題の近さのみ。取得するなら部屋設定を議論時間・人数・ウルフ数へ拡張する（デフォルト構成必須に注意） |
| ゲーミフィケーション (Minor) | 1 | 実績等3つ以上+DB永続化。統計と同時にやると効率的 |

## 3. 非推奨（相性またはコストの問題）

| モジュール | pt | 理由 |
|---|---|---|
| トーナメント (Minor) | 1 | 1戦約6分と短く回せる点は好相性だが、ブラケット管理と部屋管理の二重実装になる |
| 多言語対応 (Minor) | 1 | お題マスタと議論UIの翻訳量が多い。やるなら最初からi18n設計必須 |
| WCAG 2.1 AA (Major) | 2 | リアルタイム議論ゲームで完全対応は難度が高い |
| ELK / Prometheus+Grafana (Major) | 2 | ゲーム本体と独立に進められるが、人数に対して運用コストが重い |
| マイクロサービス (Major) | 2 | 人数と期間に対してアーキテクチャコストが重い |
| ブロックチェーン (Major/Minor) | 2/1 | スコア保存の必然性が薄い |

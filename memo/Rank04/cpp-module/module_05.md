# C++ Module 03

###  Module 05 の主要テーマ：『反復と例外』

このモジュールは、これまでのオブジェクト指向設計からさらに一歩進み、**「プログラムの堅牢性（エラーが起きても安全に動き続ける性質）」** を高めるための非常に重要な概念を学ぶ構成になっています。<br>
本モジュールのサマリーには **「Repetition and Exceptions（反復と例外）」** と題されています 。
一言で言えば、**「予期せぬエラー（例外）が発生したときに、プログラムをクラッシュさせずに優雅に処理する方法」** と **「手続き型の汚い分岐（if/elseの羅列）を排除し、美しく処理を共通化・自動化する方法」** を学びます。

具体的には、以下の3つの大テーマに分かれています。

### 1. 例外処理 (Exception Handling)

C言語では、関数が失敗したときに `NULL` や `-1` などの「エラーコード」を返し、呼び出し側で毎回 `if (ret == -1)` とチェックしていました。
C++の例外処理（`try`, `catch`, `throw`）を使うことで、エラーの発生（検知）とエラーの処理（解決）を明確に分離できるようになります。

* **学ぶこと**: カスタム例外クラスの作成、`std::exception` の継承、適切なタイミングでの例外のシグナル（`throw`）。

### 2. 抽象クラスとポリモーフィズム (Abstract Classes & Polymorphism)

Module 04 で学んだ「サブタイプ多態性」をさらに深め、**実体のない概念としてのクラス（抽象クラス）** を設計します。

* **学ぶこと**: 純粋仮想関数（`virtual void func() = 0;`）の定義、基底クラスへの共通処理（エラーチェック等）のカプセル化。

### 3. デザインパターンとリファクタリング (Design Patterns)

「大量の `if/else if/else` を使った、プール（Piscine）のような泥臭いコードは卒業しよう」という明確なメッセージがSubjectに込められています 。

* **学ぶこと**: 状況に応じて動的に適切なオブジェクトを生成する「ファクトリ（Factory）パターン」の基礎、**関数ポインタの配列**を用いたスマートな条件分岐の駆逐。

#### 💡 ストーリーの要約

* **ex00**: 1〜150の「ランク（評定）」を持つ官僚を作ります 。ランク外の数字を入れようとすると、「おい、そんなランクは存在しないぞ！」とプログラムが**例外を発生**させます 。

* **ex01**: 官僚に「書類への署名」という仕事をさせます 。書類ごとに「署名に必要なランク」が決まっており、頼まれた官僚のランクが足りないと、書類が「お前のランクじゃ署名できない！」と**例外を投げます** 。

* **ex02**: 書類を抽象化し、実行すると「木を植える」「ロボトミー手術をする」「大統領の恩赦を与える」という実務を行わせます 。ここでも、実行に必要なランクが足りなければ**例外でガード**します 。

* **ex03**: 官僚たちが書類をいちいち手で作るのが面倒になったので、何も文句を言わない「インターン（見習い）」を雇います 。インターンに「〇〇の書類を作って」と文字列で頼むと、サッと適切な書類を作ってくれる魔法（**関数ポインタの配列による自動化**）を実装します 。

### ⚠️ Module 05 で特に注意すべき「落とし穴」

1. **Orthodox Canonical Form (OCF) の徹底**
* 例外クラスそのものは OCF でなくても良いと Subject に書かれていますが、それ以外の `Bureaucrat`, `AForm` などの主要クラスはすべて OCF を満たす必要があります 。

* 特に `const` 属性のメンバ（官僚の名前など）があるクラスの `operator=`（コピー代入演算子）をどう実装するか、が問われます 。

2. **メモリリークの防止**
* ex03 ではインターンが `new` で書類を生成してポインタで返します 。これを受け取った側（`main` 関数など）で、最後に必ず `delete` を行わないとメモリリークになります 。

3. **ヘッダファイルへの実装禁止**
* 例外クラスの `what()` などの実装をヘッダファイル（`.hpp`）内にインラインで書いてしまうと、その時点でそのエクササイズは 0 点になります（テンプレート関数を除く） 。必ず `.cpp` に分離します 。

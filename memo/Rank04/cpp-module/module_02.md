## Orthodox Canonical Form

**Orthodox Canonical Form**（正統的標準クラス形式）とは、C++においてオブジェクトのコピーや代入を安全かつ予測可能に行うために、クラスが最低限備えておくべき4つの特別なメンバ関数の構成要素を指します。

C++の言語仕様上、これらを記述しなくてもコンパイラが自動生成することがありますが、特にメモリの動的確保（`new`など）を行うクラスでは、明示的に定義しないとメモリリークや二重解放（double free）などの深刻なバグの原因となります。

### 構成される4つの要素

1.  **デフォルトコンストラクタ (Default Constructor)**:
    *   引数なしでオブジェクトを初期化します。
    *   例: `ClassName();`
2.  **コピーコンストラクタ (Copy Constructor)**:
    *   既存の同じ型のオブジェクトを元に、新しいオブジェクトを複製して初期化します。
    *   例: `ClassName(const ClassName &other);`
3.  **コピー代入演算子 (Copy Assignment Operator)**:
    *   既に存在するオブジェクトに対し、別のオブジェクトの内容を上書きコピーします。
    *   例: `ClassName &operator=(const ClassName &other);`
4.  **デストラクタ (Destructor)**:
    *   オブジェクトの寿命が尽きたときに呼び出され、リソースの解放などを行います。
    *   例: `~ClassName();`

## 固定小数点数表現の要約

「Introduction to Fixed Point Number Representation（固定小数点数表現の基礎）」の要約。


この記事は、コンピュータ上で実数（小数）を表現する手法である「固定小数点数」の仕組みと、その利点・欠点について解説しています。

*   **基本概念と用途**:
    *   固定小数点数は、小数を含む数値を表現するための手法です。
    *   精度よりも処理速度が重視されるデジタル信号処理（DSP）やゲームなどの分野で広く利用されています。
*   **バイナリポイント（2進小数点）**:
    *   10進数の小数点と同様に、数値の整数部と小数部を分ける役割を果たします。
    *   小数点の左側のビットは2の正の累乗の重みを持ち、右側のビットは2の負の累乗（2の-1乗、2の-2乗など）の重みを持ちます。
*   **仕組みと表現方法**:
    *   固定小数点数は、「全体のビット幅」と「バイナリポイントの位置」という2つのパラメータで定義されます。
    *   整数のビット列に対して、特定の場所に暗黙のバイナリポイントを固定（想定）することで小数を表現します。
*   **負の数の扱い**:
    *   整数と同じように「2の補数」を用いて負の数を表現します。
    *   これにより、正の数でも負の数でも、加減算やシフト演算（2での除算など）を全く同じように処理できます。
*   **メリットとデメリット**:
    *   **メリット**: コンピュータに既存する整数の演算回路をそのまま再利用できるため、浮動小数点演算と比較して桁違いに高速です。
    *   **デメリット**: 浮動小数点数と比べると、表現できる数値の範囲が狭く、精度も制限されます。
*   **C言語での利用**:
    *   C言語には固定小数点用の専用データ型は存在しません。
    *   しかし、固定小数点の演算処理は整数と全く同じであるため、標準の `int` 型などをそのまま流用して演算を行うことが可能です。

総じて、固定小数点数は表現できる範囲や精度と引き換えに、圧倒的な計算スピードを得るための強力な選択肢となります。

## 記事の重要ポイント：なぜ固定小数点数が必要か

### 整数（Integer）の特徴：正確だが、精密度に欠ける

* **正確性（高）**: 「2」は間違いなくきっかり「2」であり、演算を行っても（オーバーフローしない限り）ビット単位で完全に正確な結果が出ます。

* **精密度（低）**: 小数部を保持できないため、細かい情報が失われます（例：5÷2も4÷2も結果は同じ「2」になってしまう）。

例え: 「レンガ」。立方体を完璧に組み立てることはできるが、滑らかな球体を作るのには向いていない。

### 浮動小数点数（Float）の特徴：精密だが、正確性に欠ける

* **精密度（高）**: 情報を意図的に切り捨てることはなく、細かい階調の表現が可能です。

* **正確性（低）**: 計算結果が正解とビット単位で完全に一致することは文字通り「ほぼ不可能」です。

例え: 「シリコン粘土（スライム）」。複雑な曲面を作る柔軟性はあるが、角が尖った完璧な立方体を作るのには向いていない。

### なぜ浮動小数点数には誤差が生じるのか？
* 10進数で「1/3」を有限の桁数（0.3333...）で正確に表すことができないのと同じように、2進数においてもすべての分数を正確に表現できるわけではないからです。

したがって、浮動小数点数を扱う以上、小さな「丸め誤差」が生じるのは避けられない構造上の宿命です。プログラマーはこの特性（どのように機能しているのか）を正しく理解し、誤差によるトラブルを防ぐ工夫をする必要があります。

### 浮動小数点数の仕組みと「イリュージョン」
浮動小数点数は、符号、指数、仮数の3つのパーツで構成される IEEE-754 標準に基づいています。
* **正確ではない比較**: `0.1` のような単純な小数も、バイナリ（2進数）では無限小数になるため、`==` での比較が期待通りにいかないことがあります。
* **指数の罠**: 非常に大きな数に小さな数を足すと、小さい数が「飲み込まれて」消えてしまうことがあります（Loss of Significance）。



---

### 静的定数 `fractionalBits`
課題では `static const int fractionalBits = 8;` と指定されています。
* これは、32ビットの `int` のうち、下位8ビットを小数部分として扱うことを意味します。
* つまり、整数値の `1` は、このクラスの内部では $1 \ll 8$（つまり 256）として保持されることになります。


```sh
static: オブジェクト全体で1つだけ共有される

const: あとから書き換えられない定数である

int: 整数型の変数で

fractionalBits: 小数部の桁数を覚えておくためのもの。

= 8: その中身は、常に 8 という数字（リテラル）である。
```

**なぜここで static を使うのか？**<br>		 
今回の Fixed クラスでは、「小数部のビット数は絶対に8である」という絶対的なルールがあります。すべての Fixed オブジェクトが fractionalBits = 8 という同じ情報を持つのに、オブジェクトを作るたびにメモリを消費して「8」を持たせるのは無駄です。
そのため、static をつけて「クラス全体で1つの共通ルール」として定義しているのです。

## コピーコンストラクタ
コピーコンストラクタは、C++において**「既存のオブジェクトと同じ内容を持つ、新しいオブジェクトを作成する」**ために呼び出される特別なコンストラクタです。

---

### 1. コピーコンストラクタの基本構造

コピーコンストラクタは、自分自身のクラスの参照（通常は `const`）を引数として受け取ります。

```cpp
// クラス内での宣言例
Fixed(const Fixed& other);
```

#### なぜ「参照 (`&`)」が必要なのか？
もし参照ではなく「値渡し」で引数を受け取ろうとすると、引数を渡す際にも「コピー」が発生してしまい、そのコピーのためにまたコピーコンストラクタが呼ばれ……という**無限ループ（再帰）**に陥ってしまいます。これを防ぐために、参照で受け取ることが文法上決まっています。

「参照（&）」を使わない場合に何が起きるのか

この問題を理解する鍵は、**「関数に値を渡すという行為そのものが、実はコピーを発生させている」**という点にあります。

---

### 1. 「値渡し」で何が起きているか？
通常、C++で関数に引数を「値渡し」で渡すと、関数の内部で使うための「コピー」が作成されます。

```cpp
void func(int n); // intを「値渡し」する関数

int main() {
    int x = 10;
    func(x); // xの値が「コピー」されて、関数の引数 n に入る
}
```

このとき、`x` を `n` にコピーするために、コンピュータは単純にメモリを複製します。

---

### 2. コピーコンストラクタが「値渡し」だったら？
ここで、もしコピーコンストラクタの引数が参照（`&`）ではなく、ただの「値渡し」だったと仮定してみましょう。

```cpp
// もし、こんな定義が許されたとしたら...（実際はコンパイルエラーになります）
Fixed::Fixed(Fixed other) {
    this->value = other.value;
}
```

この状態で、`Fixed b(a);`（`a` を元に `b` を作る）を実行しようとすると、以下の連鎖が発生します。

1.  **`Fixed b(a);` を実行しようとする。**
2.  コピーコンストラクタが呼び出される。
3.  しかし、引数が「値渡し」なので、実引数 `a` を仮引数 `other` に**コピーして渡す必要がある。**
4.  「`a` を `other` にコピーする」ために、**再びコピーコンストラクタを呼び出そうとする。**
5.  その新しいコピーコンストラクタの引数を作るために、**またコピーコンストラクタを呼び出そうとする……。**



これが**無限ループ（無限再帰）**の正体です。「コピーを作るための関数」を実行するために「コピー」が必要になり、永遠に処理が終わらなくなってしまいます。

---

### 3. 「参照 (&)」を使うとどう解決するか？
「参照」とは、新しいコピーを作るのではなく、**「既存のオブジェクトに別名を付ける（リモコンを渡すようなもの）」**という操作です。

```cpp
// 正しい定義
Fixed::Fixed(const Fixed& other) {
    this->value = other.value;
}
```

「参照」で渡す場合、実引数 `a` を `other` という名前で直接操作するだけなので、**引数を受け取る段階で「コピー」が発生しません。**

1.  **`Fixed b(a);` を実行する。**
2.  コピーコンストラクタが呼ばれる。
3.  引数は「参照」なので、新しいコピーは作らず、`a` を `other` という別名でそのまま参照する。
4.  `other.value`（つまり `a.value`）の中身を `this->value`（`b.value`）に代入する。
5.  **無事に終了！**

---

### まとめ
* **値渡し**: 「中身を複製した新しい箱」を作る行為。これ自体がコピーコンストラクタを必要とする。
* **参照渡し**: 「今ある箱」にラベルを貼って直接指し示す行為。コピーが発生しない。

だからこそ、コピーコンストラクタの引数は**「コピーを発生させずに、コピー元のオブジェクトにアクセスできる」**参照型でなければならないのです。

この「コピーを発生させないために参照を使う」という理屈は、Module 02の「Orthodox Canonical Form」を理解する上で非常に重要です。

### 2. いつ呼び出されるのか？

コピーコンストラクタは、主に以下の3つのタイミングで自動的に呼び出されます。

1.  **オブジェクトを別のオブジェクトで初期化するとき**
    * `Fixed b(a);` または `Fixed b = a;` （※代入ではなく初期化として機能する場合）
2.  **関数にオブジェクトを「値渡し」で渡すとき**
    * `void myFunction(Fixed arg)` という関数に `myFunction(a)` として渡すと、`arg` を作るためにコピーが発生します。
3.  **関数からオブジェクトを「値」として返すとき**
    * `Fixed getFixed()` という関数が `return a;` する際、戻り値用のオブジェクトを作るためにコピーが発生します。

### 3. 「浅いコピー」と「深いコピー」

コピーコンストラクタを理解する上で最も重要なのが、メモリの扱い方です。



### 浅いコピー (Shallow Copy)
デフォルトのコピーコンストラクタ（自分で定義しなかった場合にコンパイラが作るもの）は、メンバ変数をそのままコピーします。
* [cite_start]今回の `Fixed` クラスのように、メンバが `int value` だけであれば問題ありません [cite: 676]。

### 深いコピー (Deep Copy)
メンバ変数に**ポインタ（動的メモリ確保した領域）**が含まれる場合、浅いコピーだと「ポインタのアドレス」だけがコピーされてしまいます。その結果、2つのオブジェクトが同じメモリを指してしまい、一方がデストラクタでメモリを解放すると、もう一方のオブジェクトが壊れてしまいます。これを防ぐために、新しいメモリを確保して中身をコピーするのが「深いコピー」です。

---

### 4. なぜ自分で実装するのか？（Orthodox Canonical Form）

C++の設計ルール（Orthodox Canonical Form）では、たとえ単純なクラスであっても、コピーコンストラクタを明示的に定義することが推奨されます。 

これにより、
* 将来的にクラスに複雑なメンバ（ポインタなど）が追加された際のバグを防げる。
* 今回の課題のように、デバッグメッセージ（`Copy constructor called`）を出して、プログラムの挙動を完全に把握できる。

というメリットがあります。

---

### まとめ：Ex00での役割
`Fixed b( a );` を実行したとき：
1.  新しいメモリ領域が `b` のために確保される。
2.  コピーコンストラクタが呼ばれ、`a` の `getRawBits()` を通じて `value` を取得する 。
3.  取得した値を `b.value` に代入する。

これが完了すると、`a` と `b` は「同じ値を持っているが、実体としては別のオブジェクト」として存在することになります。

## 1. コピーコンストラクタを使うメリット
結論から言うと、コピーコンストラクタの最大のメリットは**「既存のオブジェクトの状態を完全に引き継いだ『独立した複製』を安全に作れること」**にあります。

### オブジェクトの独立性の確保（深いコピー）
C++で最も重要なメリットは、メモリ管理の安全性です。
クラスがポインタをメンバに持っている場合、単純なビットコピー（浅いコピー）では、コピー元とコピー先が同じメモリを指してしまいます。これでは片方を変更するともう片方も変わってしまい、片方が破棄されるともう片方は「存在しないメモリを指す（ダングリングポインタ）」状態になります。
コピーコンストラクタを自分で定義することで、新しいメモリを確保し中身をコピーする**「深いコピー」**が可能になり、オブジェクト同士の独立性が守られます。


### Orthodox Canonical Form への準拠
Module 02のルールにある通り、コピーコンストラクタを明示的に実装することは、C++の「正統的標準形式」を守ることになります。これにより、どのような状況下でもクラスが予測可能で安定した挙動を示すことが保証されます。

## 2. どのような時に使用されるか（呼び出しタイミング）

コピーコンストラクタは、プログラマが明示的に呼び出すだけでなく、C++の仕組みの中で**自動的に**呼び出される場面が非常に多いです。

### ① オブジェクトを別のオブジェクトで初期化するとき
これが最も一般的なケースです。
```cpp
Fixed a;
Fixed b(a);   [cite_start]// ここでコピーコンストラクタが呼ばれる [cite: 691]
Fixed c = a;  // これも代入ではなく「コピーによる初期化」なので呼ばれる
```

### ② 関数にオブジェクトを「値渡し」で渡すとき
引数としてオブジェクトを渡す際、関数のスコープ内にそのコピーが作成されます。
```cpp
void display(Fixed f) { // 値渡し
    // ...
}

Fixed a;
display(a); // aをコピーしてfを作るために呼び出される
```

### ③ 関数からオブジェクトを戻り値として返すとき
関数が終了して値を返す際、一時的なオブジェクトを作成するためにコピーが行われます。
```cpp
Fixed createFixed() {
    Fixed temp;
    return temp; // tempのコピーを呼び出し元に返すために呼び出される
}
```

### ④ 標準ライブラリ（STL）などのコンテナに格納するとき
（※Module 02ではSTLは禁止ですが、将来的な知識として重要です）
`std::vector` などに要素を追加する際、コンテナの内部メモリに要素がコピーされて格納されます。この時もコピーコンストラクタが必須となります。

## 3. 「コピー代入演算子」との違い

* **コピーコンストラクタ**: **「まだ存在しない」**新しいオブジェクトを、既存のものを元に作るときに呼ばれる。
* **コピー代入演算子**: **「すでに存在する」**オブジェクトの内容を、別の既存のもので上書きするときに呼ばれる。


---

### 1. 役割の違い

| 特徴 | デフォルトコンストラクタ | コピーコンストラクタ |
| :--- | :--- | :--- |
| **何を作る？** | [cite_start]**「空」または「初期状態」**のオブジェクト [cite: 679] | [cite_start]**「既存のオブジェクトの複製」** [cite: 680] |
| **元になるデータ** | なし（または固定の初期値） | すでにある同じクラスのインスタンス |
| **目的** | 新しく真っさらな状態から始めたい時 | 今ある状態をそのままコピーして別の場所で使いたい時 |

---

### 2. コードでの見分け方

書かれているコード（宣言や実装）を見ると、**「引数（カッコの中身）」**で一目で見分けることができます。

#### ① デフォルトコンストラクタの見分け方
**カッコの中身が空（引数なし）**です。
```cpp
// 宣言 (Fixed.hpp)
Fixed(); 

// 実装 (Fixed.cpp)
Fixed::Fixed() : value(0) { ... }
```
* コードの中に `Fixed a;` とだけ書かれていたら、このデフォルトコンストラクタが呼ばれます。

#### ② コピーコンストラクタの見分け方
**カッコの中に「自分自身のクラスの参照」**が入っています。
```cpp
// 宣言 (Fixed.hpp)
Fixed(const Fixed& other); 

// 実装 (Fixed.cpp)
Fixed::Fixed(const Fixed& other) { ... }
```
* ポイントは `const` と `&` です。これがあれば「自分と同じ型のヤツ（`other`）を連れてきて、そいつをコピーするんだな」と判断できます。

---

### 3. main関数での使われ方の違い

`ex00` の `main` 関数を例に、どちらが呼ばれているか見てみましょう。

```cpp
int main() {
    Fixed a;        // ← (1) カッコなし。デフォルトコンストラクタが呼ばれる
    Fixed b( a );   // ← (2) カッコの中に「a」がいる。コピーコンストラクタが呼ばれる
}
```



1. **`Fixed a;`**:
   「`a` という名前の新しい `Fixed` を作って。中身はとりあえず `0`（デフォルト）でいいよ」という命令です。
2. **`Fixed b( a );`**:
   「`b` という新しい `Fixed` を作って。ただし、中身は **`a` と全く同じにしてね**」という命令です。

### 演算子オーバーロードとは？

簡単に言うと、**「自作のクラスに対して、`+` や `=` や `<<` などの標準的な記号（演算子）の働きを独自に定義すること」**です。

たとえば、自作の数値クラス `Fixed a, b;` があった場合、本来なら `a.add(b)` のように関数を呼ぶ必要がありますが、演算子をオーバーロードすることで `a + b` と直感的に書けるようになります。

課題を進める上で、主に以下の3パターンの実装を理解する必要があります。

---

### 1. 最重要：コピー代入演算子 (`operator=`)

Orthodox Canonical Form（正統的標準クラス形式）で必須となる演算子です。すでに存在するオブジェクトに、別のオブジェクトの値を上書き代入する際に呼ばれます。

**【フィードバックの反映】**
*   Subjectの指示に従い、メンバ変数は `_name` ではなく `name` とします。
*   **RAIIの観点**: 代入される側が既にメモリやファイルポインタなどの「リソース」を持っていた場合、新しい値で上書きする前に**古いリソースを安全に破棄（解放）**する必要があります。

```cpp
class Character {
private:
    std::string name; // 【厳守】_name としない

public:
    // コピー代入演算子の宣言
    Character& operator=(const Character& rhs);
};

// 実装
Character& Character::operator=(const Character& rhs) {
    // 1. 自己代入チェック（a = a; のような操作を防ぐ）
    // これをしないと、RAIIに基づき自身のリソースを解放した直後に
    // 自身の（すでに消えた）値をコピーしようとしてバグになります。
    if (this != &rhs) {

        // 2. 値のコピー（ポインタなどがある場合は古いものを解放してから深いコピーをする）
        this->name = rhs.name;
    }

    // 3. 連続代入 (a = b = c;) を可能にするため、自身の参照を返す
    return *this;
}
```

### 2. 算術・比較演算子 (`+`, `-`, `>`, `==` など)

四則演算や比較を行うための演算子です。元のオブジェクトの値を変更してはいけないため、引数や関数自体に `const` をつけるのが定石です。

```cpp
class Fixed {
private:
    int value; // 【厳守】_value としない

public:
    // 加算演算子 (a + b)
    Fixed operator+(const Fixed& rhs) const {
        Fixed result;
        result.value = this->value + rhs.value;
        return result; // 新しいオブジェクトを作って返す（値渡し）
    }

    // 比較演算子 (a == b)
    bool operator==(const Fixed& rhs) const {
        return this->value == rhs.value;
    }
};
```
*   **ポイント:** `+` 演算子は、自身 (`this`) と 右辺 (`rhs`) を足した**新しい結果のオブジェクト**を返します。自身や右辺の値を書き換えてはいけません。

### 3. ストリーム挿入演算子 (`operator<<`)

`std::cout << a;` のように、自作クラスの情報を `cout` に直接流し込めるようにするためのものです。これはクラスのメンバ関数としてではなく、**クラスの外部関数**として定義します。

**【フィードバックの反映】**
入力ストリーム (`operator>>`) を実装する場合は、ここでフィードバックにあった「ストリームの状態ビット (`fail()`, `eof()`, `bad()`)」を確認し、無効な入力が来た際のエラーハンドリングを行うと非常に堅牢になります。

```cpp
#include <iostream>

// クラス外に定義する
std::ostream& operator<<(std::ostream& os, const Fixed& obj) {
    // objのゲッターなどを通じて値を取得し、ストリームに流す
    os << obj.toFloat();

    // std::cout << a << b; と連続して繋げるために、ストリームの参照をそのまま返す
    return os;
}
```

---

*   **`operator=`**: 既存オブジェクトへの上書き。自己代入チェック (`this != &rhs`) と `return *this` が必須。RAIIの観点からリソース管理に注意する。
*   **`operator+` などの算術**: 状態を変更せず、新しいオブジェクトを返す。
*   **`operator<<`**: クラス外で定義し、`std::ostream&` を受け取り・返す。
*   **命名規則**: Subjectに `name` とあれば、絶対に `_name` や `m_name` にしない。

### 1. コピーコンストラクタ (Copy Constructor)
**「新しいオブジェクトを作るとき」**に呼ばれます。

*   **役割:** すでに存在する別のオブジェクトを「設計図・初期値」として使い、**全く新しいオブジェクトをメモリ上に生成**します。
*   **呼ばれるタイミングの例:**
    ```cpp
    Character a;         // デフォルトコンストラクタ
    Character b(a);      // コピーコンストラクタ（aを元にbを新規作成）
    Character c = a;     // コピーコンストラクタ（※代入演算子に見えますが、cが新しく作られる瞬間なのでコンストラクタです）
    ```
*   **実装のポイント:**
    これから作られるまっさらなオブジェクトに対する操作なので、古いデータの削除などを気にする必要はありません。

### 2. コピー代入演算子 (Copy Assignment Operator)
**「すでに存在しているオブジェクトを上書きするとき」**に呼ばれます。

*   **役割:** すでに生成され、何らかの値（またはリソース）を持っているオブジェクトに対し、別のオブジェクトの値を**上書きコピー**します。
*   **呼ばれるタイミングの例:**
    ```cpp
    Character a;
    Character b;
    b = a;               // コピー代入演算子（すでに存在するbの中身を、aのもので上書き）
    ```
*   **実装のポイント（💡ここでRAIIの概念が重要になります！）:**
    コピー代入演算子では、上書きされる側のオブジェクトが**すでに何らかのリソース（動的に確保したメモリや、開いているファイルなど）を持っている可能性**があります。
    RAIIの原則に従うなら、新しい値を上書きする前に**「自分の持っている古いリソースを解放（破棄）する」**という手順が必要になります。また、`a = a;` のような「自分自身への代入（自己代入）」を防ぐためのチェック（`if (this != &rhs)`）が絶対に必要です。

---

### フィードバックを反映した実装例の比較

課題のフィードバックに従い、メンバ変数は `_name` ではなく `name` としています。
```cpp
class Character {
private:
    std::string name; // 【厳守】_name としない

public:
    // 1. コピーコンストラクタ
    Character(const Character& other) {
        this->name = other.name;
        // 新しく作るので、古いデータの破棄は不要
    }

    // 2. コピー代入演算子
    Character& operator=(const Character& rhs) {
        // 自己代入チェック（自分自身を代入しようとしていないか確認）
        if (this != &rhs) {
            // ※もしここで動的メモリ等(ポインタ)を扱っている場合、
            // RAIIに基づき、新しい値をコピーする前に古いリソースを解放(delete)する必要があります。
            // 今回は std::string なのでそのまま上書きでOKです。
            this->name = rhs.name;
        }
        return *this; // 連続代入 (a = b = c) のために自身の参照を返す
    }
};

```

### まとめ

| 特徴 | コピーコンストラクタ | コピー代入演算子 (`operator=`) |
| :--- | :--- | :--- |
| **実行されるタイミング** | オブジェクトの**生成時** | 既存オブジェクトへの**上書き時** |
| **事前のリソース解放** | 不要（まっさらな状態だから） | **必要**（古いデータを持っている可能性があるから） |
| **自己代入チェック** | 不要 | **絶対に必要** (`if (this != &rhs)`) |
| **戻り値** | なし（コンストラクタのため） | 自身の参照 (`*this`) を返す |

### 1. 自己代入とは何か？

自己代入とは、**「自分自身に対して、自分自身の値を代入してしまうこと」**を指します。

```cpp
Fixed a;
a = a; // ← これが自己代入です
```

「わざわざそんな意味のないコードは書かないよ」と思うかもしれません。しかし、プログラムが複雑になり、ポインタや参照、配列などを経由してデータをやり取りするようになると、意図せず「実は同じオブジェクト同士を代入していた」というケースが発生し得ます。

### 2. なぜチェックが必要なのか？（RAIIとの深い関わり）

ここで、いただいたフィードバックにある**「RAII（Resource Acquisition Is Initialization）」**の概念が深く関わってきます。

コピー代入演算子の基本的な処理の流れは、通常以下のようになります。
1. **古いデータの破棄**（自分が現在持っているメモリなどのリソースを解放する）
2. **新しいデータの確保とコピー**（代入元のデータ領域を新しく確保し、中身をコピーする）

もし自己代入のチェックがなく、`a = a;` が実行された場合、以下のような致命的なバグが発生します。

1. `a` は、新しい値を受け入れるために**自分の古いデータを破棄（`delete` など）します**。
2. 次に、代入元（`other`）のデータをコピーしようとします。
3. しかし、代入元である `other` は自分自身（`a`）なので、**コピーしたかったデータは手順1ですでに消滅しています**。
4. 結果として、ゴミデータをコピーしてしまうか、プログラムがクラッシュ（Segmentation fault）を引き起こします。

このような悲劇を防ぐために、「もし代入元（`other`）が自分自身（`this`）だったら、何もしないでそのまま返す」という `if` 文のチェックが絶対に必要になります。

### 3. コードの仕組み

```cpp
if (this != &other) {
    // ...
}
```

*   `this`: 現在処理を実行している**自分自身のオブジェクトのメモリアドレス（ポインタ）**です。
*   `&other`: 引数として渡されてきた**代入元のオブジェクトのメモリアドレス**です。

つまり、値（中身）が同じかどうかを比較しているのではなく、**「メモリ上で全く同じ場所に存在する、同一のインスタンスかどうか」**を比較しています。同一人物であれば、代入処理を丸ごとスキップします。

### 4. 今回の `Fixed` クラスにおける意味合い

今回の `Fixed` クラスは内部に `int value` という単純な変数しか持っていない（動的に確保したメモリ等のリソースを持っていない）ため、実はこのチェックがなくてもプログラムがクラッシュすることはありません。上書きされても安全です。

しかし、C++ Module 02 における最大の学習目的は**「Orthodox Canonical Form（正統的標準クラス形式）」のお作法を手に馴染ませること**です。今後、文字列（ポインタ）やファイルストリームなどを扱うクラスを作成する際、このチェックを書き忘れると即座にバグに繋がります。そのため、リソースの有無に関わらず、コピー代入演算子には必ずこの自己代入チェックを含めることが「絶対に守るべきルール」となっています。

## ex01: Towards a more useful fixed-point number class

**「挿入演算子（`<<`）のオーバーロード」** は、`Fixed` オブジェクトを `std::cout << a;` のように直接出力できるようにするためのものです。

この機能は、クラスの外部（グローバルスコープ）の関数として、**`Fixed.hpp` に宣言**し、**`Fixed.cpp` に実装**します。

---

### 1. 該当部分のコード

**【Fixed.hpp】（ヘッダファイルでの宣言）**
```cpp
// 【重要】クラスの「外」に宣言します
std::ostream& operator<<(std::ostream& os, const Fixed& fixed);
```

**【Fixed.cpp】（ソースファイルでの実装）**
```cpp
#include "Fixed.hpp"

// 挿入演算子のオーバーロードの実装
std::ostream& operator<<(std::ostream& os, const Fixed& fixed) {
    // Subjectの指示通り、toFloat() を使って浮動小数点数表現をストリームに挿入する
    os << fixed.toFloat();

    // 【Feedback: streamの仕組み】
    // 戻り値としてストリーム自身の参照を返すことで、連続した出力や状態の伝播が可能になります。
    return os;
}
```

---

### 2. コードの詳しい説明

#### なぜクラスの「外」に定義するのか？
通常、クラスのメンバ関数として演算子をオーバーロードすると、左辺のオブジェクトがそのクラス自身である必要があります（例：`a + b` なら `a.operator+(b)`）。
しかし、`std::cout << a;` の場合、左辺にあるのは `Fixed` ではなく `std::ostream` 型のオブジェクト（`std::cout`）です。`std::ostream` クラスは私たちが書き換えることができない標準ライブラリのクラスなので、`Fixed` クラスの外側に **「左辺に `std::ostream`、右辺に `Fixed` を取る関数」** として定義してあげる必要があります。

#### 内部の処理（`os << fixed.toFloat();`）
Subjectに *"inserts a floating-point representation of the fixed-point number"*（固定小数点数の**浮動小数点数表現**を挿入する）と明確に指示されています。
そのため、生のビット値（`value`）をそのまま流し込むのではなく、Exercise 01 で新たに実装するメンバ関数 `toFloat()` を呼び出し、`float` 型に変換してからストリーム（`os`）に渡しています。

#### 戻り値が `std::ostream&` である理由（Feedbackとの関連）
戻り値として `os` をそのまま返しているのは、**「連続代入（チェーン）」** を可能にするためです。
```cpp
std::cout << a << " is a number." << std::endl;
```
このコードは、左から順番に `(std::cout << a)` が実行され、その結果（つまり `std::cout` の参照）が返ってくることで、次に `std::cout << " is a number."` が実行される、という仕組みになっています。

**💡 ストリーム状態ビット（Feedback）との関連**
戻り値としてストリームの参照を正しく返すことで、呼び出し元でストリームの状態（エラーが起きていないかなど）を追跡できるようになります。今回は出力（`<<`）なのでエラーになることは稀ですが、後々入力（`>>`）のオーバーロードを実装する際には、フィードバックにあった `fail()` などの状態ビットを活用したエラーハンドリングが非常に重要になってきます。

## ex02: Now we're talking

この演習では、`Fixed` クラスに「演算子オーバーロード（Operator Overloading）」を大量に追加し、組み込み型（`int` や `float`）と同じように直感的に計算や比較ができるようにします。

---

###  設計とポイント

今回追加する機能は以下の4つのグループに分かれます。

1.  **比較演算子 (Comparison Operators)**:
    *   `>`, `<`, `>=`, `<=`, `==`, `!=`
    *   内部の `value`（生のビット値）を直接比較するのが最も効率的です。
2.  **算術演算子 (Arithmetic Operators)**:
    *   `+`, `-`: `value` 同士をそのまま足し引きし、結果を新しい `Fixed` オブジェクトとして返します。
    *   `*`, `/`: 一度 `toFloat()` で浮動小数点数に戻して計算し、その結果から再度 `Fixed` オブジェクトを構築するのが一番安全で誤差の少ない方法です。
3.  **増減演算子 (Increment/Decrement Operators)**:
    *   `++a` (前置), `a++` (後置), `--a` (前置), `a--` (後置)。
    *   問題文にある「最小表現可能単位 $\epsilon$ (epsilon)」は、固定小数点数において `value` を `1` だけ増減させることに相当します。つまり `this->value++` とするだけで、自動的に $+0.00390625$ ($1/256$) されます。
4.  **静的メンバ関数 (Static Member Functions)**:
    *   `min`, `max`（それぞれ非const版とconst版のオーバーロード）。
    *   2つの引数を比較し、小さい方/大きい方の参照を返します。

---

### 実装の解説：特に重要なポイント

#### 前置(`++a`) と 後置(`a++`) の違い
*   **前置 (`operator++()`)**: 自身の `value` を `1` 増やし、その変化した**自分自身への参照** (`Fixed&`) を返します。
*   **後置 (`operator++(int)`)**: ダミーの引数 `int` を取ることで前置と区別します。値を増やす前に自分のコピー（`temp`）を作り、自身を増やした上で、**古いコピーを値として**返します。このため、後置のほうがコピーが1回多く発生し、若干処理が重くなります。

#### なぜ足し算は生のビット値でできるのに、掛け算はfloatにするのか？
*   **足し算**: `(1.5 + 2.5)` は、内部的には `(1.5 * 256) + (2.5 * 256)` です。分配法則により `(1.5 + 2.5) * 256` となるため、生のビット値をそのまま足せば正解になります。
*   **掛け算**: `(1.5 * 256) * (2.5 * 256)` をそのまま計算すると、結果が `256` 倍されすぎてしまい（オーバーフローの危険大）、ビットシフトによる補正が複雑になります。そのため、一度 `toFloat()` で戻して計算するのが最も安全で確実です。


素晴らしいです！出力結果がSubjectの要求（計算結果）と完全に一致し、かつ不必要な `Copy assignment operator called` のメッセージも消えました。

これで、C++が裏側でどのように一時オブジェクトを作り、コピーし、そして不要になった瞬間に破棄しているか（デストラクタが呼ばれているか）が、ログの出力から手に取るように分かるようになりましたね。

あなたの `Fixed` クラスは、メモリリークを起こさず、C++の作法（Orthodox Canonical Form）に完全に則った非常に堅牢なクラスになっています。

### 1. `static` で宣言すると `Fixed::max(a, b)` と呼び出せるのはなぜ？

**結論：`static` をつけると、その関数が「特定のオブジェクト（インスタンス）」ではなく、「クラスそのもの」に属するようになるからです。**

通常、クラスのメンバ関数を呼び出すには、まず実体（オブジェクト）を作る必要があります。
```cpp
Fixed a;
a.doSomething(); // aという実体を通して呼び出す
```
これは、関数の中で `this`（そのオブジェクト自身のデータ）を使うためです。

しかし、2つの値の大小を比較する `max` 関数は、引数として `a` と `b` を受け取っているので、特定のオブジェクトの `this` を必要としません。単なる「便利な計算ツール」です。

関数の頭に `static` をつけると、「この関数は `this` を使わないので、オブジェクトを作らなくても、クラス名から直接呼び出していいよ」という宣言になります。その結果、スコープ解決演算子 `::` を使って `Fixed::max(a, b)` のように呼び出せるようになります。

### 2. `(a < b) ? a : b;` この三項演算子の意味は？

**結論：`if-else` 文を1行で短く書くための省略記法です。**

三項演算子は `条件式 ? 真のときの値 : 偽のときの値` という構文になっています。

`min` 関数の中にある `(a < b) ? a : b;` を通常の `if-else` に書き換えると、以下のようになります。

```cpp
if (a < b) {
    return a; // aのほうが小さければ、aを返す
} else {
    return b; // そうでなければ（bのほうが小さいか同じなら）、bを返す
}
```

この4行の処理を、1行でスッキリと書くことができるのが三項演算子の最大のメリットです。

### 3. `min`, `max` をそれぞれ2回書いている（オーバーロードしている）理由は？

**結論：`const`（定数）なオブジェクトと、通常の（書き換え可能な）オブジェクトの両方に正しく対応するためです。**

C++では、変数を `const` で宣言すると「この値は絶対に書き換えられない」という強力な保証がつきます。ex02のSubjectの `main` 関数にも、以下のようなコードがありましたね。

```cpp
Fixed a;
Fixed const b( Fixed( 5.05f ) * Fixed( 2 ) ); // bはconst（定数）！
```

ここで、もし `min` 関数が **通常の（constが付いていない）バージョン** の1つしかなかったとします。
```cpp
Fixed& Fixed::min(Fixed& a, Fixed& b);
```
この関数に `const` である `b` を渡そうとすると、コンパイラが「引数として受け取った関数の中で値を書き換えられてしまうかもしれない！」と判断し、**コンパイルエラー**を出してしまいます。

そこで、引数も戻り値も絶対に書き換えないことを保証する **`const` バージョン** をもう1つ用意してあげる必要があります。
```cpp
const Fixed& Fixed::min(const Fixed& a, const Fixed& b);
```

こうして2つ書いておく（関数のオーバーロード）ことで、コンパイラが自動的に以下のように使い分けてくれます。

*   `Fixed::max(a, c)`（両方とも通常の変数）→ **通常の `max` が呼ばれる**（返ってきた値を後で書き換えられる）
*   `Fixed::max(a, b)`（片方でも `const` な変数が混ざっている）→ **`const` 版の `max` が呼ばれる**（返ってきた値は書き換え不可になる）

---

**💡 フィードバックとの繋がり（C++の安全性）**
この「`const` を正しく使い分ける（Const Correctness）」という考え方は、フィードバックでいただいた「RAII」や「ストリームのエラーハンドリング」と同じく、**「意図しないデータの破壊を防ぎ、コンパイル時点でエラーに気づける安全な設計にする」**というC++の根本的な思想に基づいています。

## ex03: BSP 

この課題の目的は、ここまで作ってきた強力な `Fixed` クラスを活用して、**「ある点（Point）が、3つの頂点からなる三角形の内部にあるかどうか」を判定するアルゴリズム**を実装することです。

#### 1. Point クラスの作成
まず、2D平面上の点を表す `Point` クラスを作成します。これも当然 **Orthodox Canonical Form** で作成します。
*   **メンバ変数**:
    *   `Fixed const x;`
    *   `Fixed const y;`
    *   ※ここでのポイントは `const` がつ与えられていることです。一度座標を決めたら変更できない仕様にする必要があります。

#### 2. bsp 関数の実装
次に、以下の関数を実装します。
```cpp
bool bsp( Point const a, Point const b, Point const c, Point const point);
```
*   `a`, `b`, `c`: 三角形の3つの頂点。
*   `point`: 判定したい点。
*   戻り値: 点が三角形の**完全に内部**にあれば `true`、外側や**辺・頂点の上**にあれば `false`。

#### 3. 数学的なアプローチ（外積を利用した判定）
この問題は、ベクトルの「外積（Cross Product）」を使うと美しく解けます。



点 `P` が三角形 `ABC` の内部にあるための条件は、
*   辺 `AB` から見て `P` が同じ側にある。
*   辺 `BC` から見て `P` が同じ側にある。
*   辺 `CA` から見て `P` が同じ側にある。

具体的には、外積 $\vec{AB} \times \vec{AP}$、$\vec{BC} \times \vec{BP}$、$\vec{CA} \times \vec{CP}$ を計算し、**これら3つの外積の符号（プラスかマイナスか）が全て一致**していれば、点は三角形の内部にあると判定できます。
（1つでも `0` になれば、それは辺の上にあることを意味するので `false` とします）。

---


### 1. `crossProduct` 関数（外積の計算）
この関数は、2つの点から作られる「線分（ベクトル）」に対して、判定したい点 `p` が**「直線の右側にあるか、左側にあるか、あるいは直線上にあるか」**を計算する心臓部です。

*   **やっていること:**
    ベクトル $\vec{AB}$ と ベクトル $\vec{AP}$ の2次元外積を計算しています。
    計算式は以下の通りです。
    $CrossProduct = (B_x - A_x) \times (P_y - A_y) - (B_y - A_y) \times (P_x - A_x)$

*   **この計算結果（戻り値）が意味するもの:**
    *   **プラス ( $> 0$ ):** 点 `p` は、直線ABに向かって「左側」にある。
    *   **マイナス ( $< 0$ ):** 点 `p` は、直線ABに向かって「右側」にある。
    *   **ゼロ ( $== 0$ ):** 点 `p` は、直線ABの「ちょうど真上（境界線上）」にある。

### 2. `bsp` 関数（判定のメインロジック）

#### ステップ1：3つの辺に対する判定
```cpp
Fixed cp1 = crossProduct(a, b, point);
Fixed cp2 = crossProduct(b, c, point);
Fixed cp3 = crossProduct(c, a, point);
```
三角形を構成する3つの辺（A→B、B→C、C→A）すべてに対して、判定対象の `point` が左右どちらにいるのかを計算します。
例えるなら、三角形の周りをぐるっと歩きながら、「対象の点が常に自分から見てどっちの方向にあるか」を確認している状態です。

#### ステップ2：境界線の除外（Subjectの条件クリア）
```cpp
Fixed zero(0);

if (cp1 == zero || cp2 == zero || cp3 == zero)
    return false;
```
Subjectには「厳密に内側（Strictly inside）のみ True とする」と指定されています。
外積の計算結果が `0` になるということは、点が「辺の上」または「頂点と重なっている」ことを意味します。この時点で「厳密に内側」ではないため、即座に `false` を返して処理を弾いています。

#### ステップ3：符号の一致確認（内側かどうかの最終ジャッジ）
```cpp
bool isPositive = (cp1 > zero) && (cp2 > zero) && (cp3 > zero);
bool isNegative = (cp1 < zero) && (cp2 < zero) && (cp3 < zero);

return isPositive || isNegative;
```
最後に、点が三角形の内側にあるかどうかの結論を出します。

*   点が三角形の**完全に内側**にある場合、三角形の周りをどの辺から見ても、点は**「すべて左側」**または**「すべて右側」**に見えます。（つまり、外積の結果が「全部プラス」か「全部マイナス」のどちらかになります）。
*   逆に、点が三角形の**外側**にある場合、「この辺から見ると左だけど、あの辺から見ると右」という矛盾が生じます。（外積の結果にプラスとマイナスが混ざります）。

そのため、`isPositive`（すべてプラス）か `isNegative`（すべてマイナス）の**どちらか一方が True であれば、点は完全に内側に閉じ込められている**と証明できるため、その結果を `return` しています。

### 1. コンストラクタ群（初期化子リストの活用）
```cpp
Point::Point() : x(0), y(0) {}
Point::Point(const float x, const float y) : x(x), y(y) {}
Point::Point(const Point& other) : x(other.x), y(other.y) {}
```
*   **解説:** ここでは「初期化子リスト（`: x(0), y(0)` のような書き方）」が使われています。
*   **なぜこの書き方なのか？:** Subjectの指示により、`Point` クラスのメンバ変数は `Fixed const x;` のように **`const`（定数）** として宣言されています。`const` な変数は、作られた「後」に値を代入することができません。したがって、コンストラクタの中括弧 `{}` の中で `this->x = 0;` と書くとコンパイルエラーになります。**「オブジェクトが生まれる瞬間に値を決定する」初期化子リスト**を使うのが、`const` メンバを初期化する唯一の正しい方法です。

### 2. デストラクタとゲッター
```cpp
Point::~Point() {}

Fixed const & Point::getX(void) const { return this->x; }
Fixed const & Point::getY(void) const { return this->y; }
```
*   **解説:** `Point` クラスは内部で動的メモリ（`new` など）を使っていないため、デストラクタは空で問題ありません（ここでRAIIの「自動的な後片付け」が安全に行われます）。ゲッターは値のコピーを避けるため、`Fixed const &`（定数参照）で元のデータを安全に返しています。

### 3. 最大の難所：コピー代入演算子と `const_cast`
ここが、前回お話しした「壁」であり、このコードの最も特筆すべき部分です。

```cpp
Point& Point::operator=(const Point& other) {
    if (this != &other) {
        const_cast<Fixed&>(this->x) = other.getX();
        const_cast<Fixed&>(this->y) = other.getY();
    }
    return *this;
}
```

#### 何が起きているのか？
1.  Subjectは「Orthodox Canonical Formを守れ（＝**コピー代入演算子を作れ**）」と指示しています。
2.  しかし、メンバ変数は `const` なので、**普通に代入（上書き）することはできません**。
3.  そこで、C++の裏技である **`const_cast`** を使っています。

#### `const_cast` とは？
これは**「変数についている `const`（書き換え不可）というロックを、強制的に解除する」**という非常に強力で危険なキャスト（型変換）です。
`const_cast<Fixed&>(this->x)` と書くことで、「`x` は `const` だけど、今だけは普通の `Fixed` として扱って値を上書きするぞ！」とコンパイラを説き伏せています。

#### 【C++の現実（Reality Check）】
この書き方は、42の課題をクリアするため（Subjectの矛盾を解決するため）の「ハック（裏技）」としては非常によく使われますし、コンパイルも通ります。

しかし、現実のC++プログラミングにおいては、**最初から `const` として宣言された変数の値を `const_cast` で無理やり書き換えることは「未定義動作（Undefined Behavior）」**と呼ばれ、絶対にやってはいけない禁忌とされています（最悪の場合、プログラムがクラッシュしたり、最適化バグを引き起こします）。

評価の際、レビューアーから「なぜここで `const_cast` を使ったの？」と高確率で聞かれます。その時は、以下のように論理的に答えることができれば完璧です。

> 「Subjectの指示でOrthodox Canonical Formを満たすために `operator=` を実装する必要がありました。しかし、メンバ変数が `const` 指定されているため、通常の代入ができません。本来 `const_cast` で元の `const` を書き換えるのは未定義動作（UB）であり危険ですが、このSubjectの矛盾（OCFの必須化とconstメンバの共存）を解決するために、意図的にこの手法を選択しました。」

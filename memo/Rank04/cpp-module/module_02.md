## Orthodox Canonical Form

**Orthodox Canonical Form**（正統的標準クラス形式）とは、C++においてオブジェクトのコピーや代入を安全かつ予測可能に行うために、クラスが最低限備えておくべき4つの特別なメンバ関数の構成要素を指します。

C++の言語仕様上、これらを記述しなくてもコンパイラが自動生成することがありますが、特にメモリの動的確保（`new`など）を行うクラスでは、明示的に定義しないとメモリリークや二重解放（double free）などの深刻なバグの原因となります。

### 構成される4つの要素

1.  **デフォルトコンストラクタ (Default Constructor)**:
    *   引数なしでオブジェクトを初期化します。
    *   例: `ClassName();`
2.  **コピーコンストラクタ (Copy Constructor)**:
    *   既存の同じ型のオブジェクトを元に、新しいオブジェクトを複製して初期化します。
    *   例: `ClassName(const ClassName &other);`
3.  **コピー代入演算子 (Copy Assignment Operator)**:
    *   既に存在するオブジェクトに対し、別のオブジェクトの内容を上書きコピーします。
    *   例: `ClassName &operator=(const ClassName &other);`
4.  **デストラクタ (Destructor)**:
    *   オブジェクトの寿命が尽きたときに呼び出され、リソースの解放などを行います。
    *   例: `~ClassName();`

## 記事の重要ポイント：なぜ固定小数点数が必要か

### 整数（Integer）の特徴：正確だが、精密度に欠ける

* **正確性（高）**: 「2」は間違いなくきっかり「2」であり、演算を行っても（オーバーフローしない限り）ビット単位で完全に正確な結果が出ます。

* **精密度（低）**: 小数部を保持できないため、細かい情報が失われます（例：5÷2も4÷2も結果は同じ「2」になってしまう）。

例え: 「レンガ」。立方体を完璧に組み立てることはできるが、滑らかな球体を作るのには向いていない。

### 浮動小数点数（Float）の特徴：精密だが、正確性に欠ける

* **精密度（高）**: 情報を意図的に切り捨てることはなく、細かい階調の表現が可能です。

* **正確性（低）**: 計算結果が正解とビット単位で完全に一致することは文字通り「ほぼ不可能」です。

例え: 「シリコン粘土（スライム）」。複雑な曲面を作る柔軟性はあるが、角が尖った完璧な立方体を作るのには向いていない。

### なぜ浮動小数点数には誤差が生じるのか？
* 10進数で「1/3」を有限の桁数（0.3333...）で正確に表すことができないのと同じように、2進数においてもすべての分数を正確に表現できるわけではないからです。

したがって、浮動小数点数を扱う以上、小さな「丸め誤差」が生じるのは避けられない構造上の宿命です。プログラマーはこの特性（どのように機能しているのか）を正しく理解し、誤差によるトラブルを防ぐ工夫をする必要があります。

### 浮動小数点数の仕組みと「イリュージョン」
浮動小数点数は、符号、指数、仮数の3つのパーツで構成される IEEE-754 標準に基づいています。
* **正確ではない比較**: `0.1` のような単純な小数も、バイナリ（2進数）では無限小数になるため、`==` での比較が期待通りにいかないことがあります。
* **指数の罠**: 非常に大きな数に小さな数を足すと、小さい数が「飲み込まれて」消えてしまうことがあります（Loss of Significance）。



---

### 静的定数 `fractionalBits`
課題では `static const int fractionalBits = 8;` と指定されています。
* これは、32ビットの `int` のうち、下位8ビットを小数部分として扱うことを意味します。
* つまり、整数値の `1` は、このクラスの内部では $1 \ll 8$（つまり 256）として保持されることになります。

## コピーコンストラクタ
コピーコンストラクタは、C++において**「既存のオブジェクトと同じ内容を持つ、新しいオブジェクトを作成する」**ために呼び出される特別なコンストラクタです。

---

### 1. コピーコンストラクタの基本構造

コピーコンストラクタは、自分自身のクラスの参照（通常は `const`）を引数として受け取ります。

```cpp
// クラス内での宣言例
Fixed(const Fixed& other);
```

#### なぜ「参照 (`&`)」が必要なのか？
もし参照ではなく「値渡し」で引数を受け取ろうとすると、引数を渡す際にも「コピー」が発生してしまい、そのコピーのためにまたコピーコンストラクタが呼ばれ……という**無限ループ（再帰）**に陥ってしまいます。これを防ぐために、参照で受け取ることが文法上決まっています。

「参照（&）」を使わない場合に何が起きるのか

この問題を理解する鍵は、**「関数に値を渡すという行為そのものが、実はコピーを発生させている」**という点にあります。

---

### 1. 「値渡し」で何が起きているか？
通常、C++で関数に引数を「値渡し」で渡すと、関数の内部で使うための「コピー」が作成されます。

```cpp
void func(int n); // intを「値渡し」する関数

int main() {
    int x = 10;
    func(x); // xの値が「コピー」されて、関数の引数 n に入る
}
```

このとき、`x` を `n` にコピーするために、コンピュータは単純にメモリを複製します。

---

### 2. コピーコンストラクタが「値渡し」だったら？
ここで、もしコピーコンストラクタの引数が参照（`&`）ではなく、ただの「値渡し」だったと仮定してみましょう。

```cpp
// もし、こんな定義が許されたとしたら...（実際はコンパイルエラーになります）
Fixed::Fixed(Fixed other) {
    this->value = other.value;
}
```

この状態で、`Fixed b(a);`（`a` を元に `b` を作る）を実行しようとすると、以下の連鎖が発生します。

1.  **`Fixed b(a);` を実行しようとする。**
2.  コピーコンストラクタが呼び出される。
3.  しかし、引数が「値渡し」なので、実引数 `a` を仮引数 `other` に**コピーして渡す必要がある。**
4.  「`a` を `other` にコピーする」ために、**再びコピーコンストラクタを呼び出そうとする。**
5.  その新しいコピーコンストラクタの引数を作るために、**またコピーコンストラクタを呼び出そうとする……。**



これが**無限ループ（無限再帰）**の正体です。「コピーを作るための関数」を実行するために「コピー」が必要になり、永遠に処理が終わらなくなってしまいます。

---

### 3. 「参照 (&)」を使うとどう解決するか？
「参照」とは、新しいコピーを作るのではなく、**「既存のオブジェクトに別名を付ける（リモコンを渡すようなもの）」**という操作です。

```cpp
// 正しい定義
Fixed::Fixed(const Fixed& other) {
    this->value = other.value;
}
```

「参照」で渡す場合、実引数 `a` を `other` という名前で直接操作するだけなので、**引数を受け取る段階で「コピー」が発生しません。**

1.  **`Fixed b(a);` を実行する。**
2.  コピーコンストラクタが呼ばれる。
3.  引数は「参照」なので、新しいコピーは作らず、`a` を `other` という別名でそのまま参照する。
4.  `other.value`（つまり `a.value`）の中身を `this->value`（`b.value`）に代入する。
5.  **無事に終了！**

---

### まとめ
* **値渡し**: 「中身を複製した新しい箱」を作る行為。これ自体がコピーコンストラクタを必要とする。
* **参照渡し**: 「今ある箱」にラベルを貼って直接指し示す行為。コピーが発生しない。

だからこそ、コピーコンストラクタの引数は**「コピーを発生させずに、コピー元のオブジェクトにアクセスできる」**参照型でなければならないのです。

この「コピーを発生させないために参照を使う」という理屈は、Module 02の「Orthodox Canonical Form」を理解する上で非常に重要です。

### 2. いつ呼び出されるのか？

コピーコンストラクタは、主に以下の3つのタイミングで自動的に呼び出されます。

1.  **オブジェクトを別のオブジェクトで初期化するとき**
    * `Fixed b(a);` または `Fixed b = a;` （※代入ではなく初期化として機能する場合）
2.  **関数にオブジェクトを「値渡し」で渡すとき**
    * `void myFunction(Fixed arg)` という関数に `myFunction(a)` として渡すと、`arg` を作るためにコピーが発生します。
3.  **関数からオブジェクトを「値」として返すとき**
    * `Fixed getFixed()` という関数が `return a;` する際、戻り値用のオブジェクトを作るためにコピーが発生します。

---

### 3. 「浅いコピー」と「深いコピー」

コピーコンストラクタを理解する上で最も重要なのが、メモリの扱い方です。



### 浅いコピー (Shallow Copy)
デフォルトのコピーコンストラクタ（自分で定義しなかった場合にコンパイラが作るもの）は、メンバ変数をそのままコピーします。
* [cite_start]今回の `Fixed` クラスのように、メンバが `int value` だけであれば問題ありません [cite: 676]。

### 深いコピー (Deep Copy)
メンバ変数に**ポインタ（動的メモリ確保した領域）**が含まれる場合、浅いコピーだと「ポインタのアドレス」だけがコピーされてしまいます。その結果、2つのオブジェクトが同じメモリを指してしまい、一方がデストラクタでメモリを解放すると、もう一方のオブジェクトが壊れてしまいます。これを防ぐために、新しいメモリを確保して中身をコピーするのが「深いコピー」です。

---

### 4. なぜ自分で実装するのか？（Orthodox Canonical Form）

C++の設計ルール（Orthodox Canonical Form）では、たとえ単純なクラスであっても、コピーコンストラクタを明示的に定義することが推奨されます。 

これにより、
* 将来的にクラスに複雑なメンバ（ポインタなど）が追加された際のバグを防げる。
* 今回の課題のように、デバッグメッセージ（`Copy constructor called`）を出して、プログラムの挙動を完全に把握できる。

というメリットがあります。

---

### まとめ：Ex00での役割
`Fixed b( a );` を実行したとき：
1.  新しいメモリ領域が `b` のために確保される。
2.  コピーコンストラクタが呼ばれ、`a` の `getRawBits()` を通じて `value` を取得する 。
3.  取得した値を `b.value` に代入する。

これが完了すると、`a` と `b` は「同じ値を持っているが、実体としては別のオブジェクト」として存在することになります。

## 1. コピーコンストラクタを使うメリット
結論から言うと、コピーコンストラクタの最大のメリットは**「既存のオブジェクトの状態を完全に引き継いだ『独立した複製』を安全に作れること」**にあります。

### オブジェクトの独立性の確保（深いコピー）
C++で最も重要なメリットは、メモリ管理の安全性です。
クラスがポインタをメンバに持っている場合、単純なビットコピー（浅いコピー）では、コピー元とコピー先が同じメモリを指してしまいます。これでは片方を変更するともう片方も変わってしまい、片方が破棄されるともう片方は「存在しないメモリを指す（ダングリングポインタ）」状態になります。
コピーコンストラクタを自分で定義することで、新しいメモリを確保し中身をコピーする**「深いコピー」**が可能になり、オブジェクト同士の独立性が守られます。


### Orthodox Canonical Form への準拠
Module 02のルールにある通り、コピーコンストラクタを明示的に実装することは、C++の「正統的標準形式」を守ることになります。これにより、どのような状況下でもクラスが予測可能で安定した挙動を示すことが保証されます。

## 2. どのような時に使用されるか（呼び出しタイミング）

コピーコンストラクタは、プログラマが明示的に呼び出すだけでなく、C++の仕組みの中で**自動的に**呼び出される場面が非常に多いです。

### ① オブジェクトを別のオブジェクトで初期化するとき
これが最も一般的なケースです。
```cpp
Fixed a;
Fixed b(a);   [cite_start]// ここでコピーコンストラクタが呼ばれる [cite: 691]
Fixed c = a;  // これも代入ではなく「コピーによる初期化」なので呼ばれる
```

### ② 関数にオブジェクトを「値渡し」で渡すとき
引数としてオブジェクトを渡す際、関数のスコープ内にそのコピーが作成されます。
```cpp
void display(Fixed f) { // 値渡し
    // ...
}

Fixed a;
display(a); // aをコピーしてfを作るために呼び出される
```

### ③ 関数からオブジェクトを戻り値として返すとき
関数が終了して値を返す際、一時的なオブジェクトを作成するためにコピーが行われます。
```cpp
Fixed createFixed() {
    Fixed temp;
    return temp; // tempのコピーを呼び出し元に返すために呼び出される
}
```

### ④ 標準ライブラリ（STL）などのコンテナに格納するとき
（※Module 02ではSTLは禁止ですが、将来的な知識として重要です）
`std::vector` などに要素を追加する際、コンテナの内部メモリに要素がコピーされて格納されます。この時もコピーコンストラクタが必須となります。

## 3. 「コピー代入演算子」との違い

* **コピーコンストラクタ**: **「まだ存在しない」**新しいオブジェクトを、既存のものを元に作るときに呼ばれる。
* **コピー代入演算子**: **「すでに存在する」**オブジェクトの内容を、別の既存のもので上書きするときに呼ばれる。


---

### 1. 役割の違い

| 特徴 | デフォルトコンストラクタ | コピーコンストラクタ |
| :--- | :--- | :--- |
| **何を作る？** | [cite_start]**「空」または「初期状態」**のオブジェクト [cite: 679] | [cite_start]**「既存のオブジェクトの複製」** [cite: 680] |
| **元になるデータ** | なし（または固定の初期値） | すでにある同じクラスのインスタンス |
| **目的** | 新しく真っさらな状態から始めたい時 | 今ある状態をそのままコピーして別の場所で使いたい時 |

---

### 2. コードでの見分け方

書かれているコード（宣言や実装）を見ると、**「引数（カッコの中身）」**で一目で見分けることができます。

#### ① デフォルトコンストラクタの見分け方
**カッコの中身が空（引数なし）**です。
```cpp
// 宣言 (Fixed.hpp)
Fixed(); 

// 実装 (Fixed.cpp)
Fixed::Fixed() : value(0) { ... }
```
* コードの中に `Fixed a;` とだけ書かれていたら、このデフォルトコンストラクタが呼ばれます。

#### ② コピーコンストラクタの見分け方
**カッコの中に「自分自身のクラスの参照」**が入っています。
```cpp
// 宣言 (Fixed.hpp)
Fixed(const Fixed& other); 

// 実装 (Fixed.cpp)
Fixed::Fixed(const Fixed& other) { ... }
```
* ポイントは `const` と `&` です。これがあれば「自分と同じ型のヤツ（`other`）を連れてきて、そいつをコピーするんだな」と判断できます。

---

### 3. main関数での使われ方の違い

`ex00` の `main` 関数を例に、どちらが呼ばれているか見てみましょう。

```cpp
int main() {
    Fixed a;        // ← (1) カッコなし。デフォルトコンストラクタが呼ばれる
    Fixed b( a );   // ← (2) カッコの中に「a」がいる。コピーコンストラクタが呼ばれる
}
```



1. **`Fixed a;`**:
   「`a` という名前の新しい `Fixed` を作って。中身はとりあえず `0`（デフォルト）でいいよ」という命令です。
2. **`Fixed b( a );`**:
   「`b` という新しい `Fixed` を作って。ただし、中身は **`a` と全く同じにしてね**」という命令です。

## ex02: Now we're talking

この演習では、`Fixed` クラスに「演算子オーバーロード（Operator Overloading）」を大量に追加し、組み込み型（`int` や `float`）と同じように直感的に計算や比較ができるようにします。

---

###  設計とポイント

今回追加する機能は以下の4つのグループに分かれます。

1.  **比較演算子 (Comparison Operators)**:
    *   `>`, `<`, `>=`, `<=`, `==`, `!=`
    *   内部の `value`（生のビット値）を直接比較するのが最も効率的です。
2.  **算術演算子 (Arithmetic Operators)**:
    *   `+`, `-`: `value` 同士をそのまま足し引きし、結果を新しい `Fixed` オブジェクトとして返します。
    *   `*`, `/`: 一度 `toFloat()` で浮動小数点数に戻して計算し、その結果から再度 `Fixed` オブジェクトを構築するのが一番安全で誤差の少ない方法です。
3.  **増減演算子 (Increment/Decrement Operators)**:
    *   `++a` (前置), `a++` (後置), `--a` (前置), `a--` (後置)。
    *   問題文にある「最小表現可能単位 $\epsilon$ (epsilon)」は、固定小数点数において `value` を `1` だけ増減させることに相当します。つまり `this->value++` とするだけで、自動的に $+0.00390625$ ($1/256$) されます。
4.  **静的メンバ関数 (Static Member Functions)**:
    *   `min`, `max`（それぞれ非const版とconst版のオーバーロード）。
    *   2つの引数を比較し、小さい方/大きい方の参照を返します。

---

### 実装の解説：特に重要なポイント

#### 前置(`++a`) と 後置(`a++`) の違い
*   **前置 (`operator++()`)**: 自身の `value` を `1` 増やし、その変化した**自分自身への参照** (`Fixed&`) を返します。
*   **後置 (`operator++(int)`)**: ダミーの引数 `int` を取ることで前置と区別します。値を増やす前に自分のコピー（`temp`）を作り、自身を増やした上で、**古いコピーを値として**返します。このため、後置のほうがコピーが1回多く発生し、若干処理が重くなります。

#### なぜ足し算は生のビット値でできるのに、掛け算はfloatにするのか？
*   **足し算**: `(1.5 + 2.5)` は、内部的には `(1.5 * 256) + (2.5 * 256)` です。分配法則により `(1.5 + 2.5) * 256` となるため、生のビット値をそのまま足せば正解になります。
*   **掛け算**: `(1.5 * 256) * (2.5 * 256)` をそのまま計算すると、結果が `256` 倍されすぎてしまい（オーバーフローの危険大）、ビットシフトによる補正が複雑になります。そのため、一度 `toFloat()` で戻して計算するのが最も安全で確実です。


素晴らしいです！出力結果がSubjectの要求（計算結果）と完全に一致し、かつ不必要な `Copy assignment operator called` のメッセージも消えました。

これで、C++が裏側でどのように一時オブジェクトを作り、コピーし、そして不要になった瞬間に破棄しているか（デストラクタが呼ばれているか）が、ログの出力から手に取るように分かるようになりましたね。

あなたの `Fixed` クラスは、メモリリークを起こさず、C++の作法（Orthodox Canonical Form）に完全に則った非常に堅牢なクラスになっています。

## ex03: BSP 

この課題の目的は、ここまで作ってきた強力な `Fixed` クラスを活用して、**「ある点（Point）が、3つの頂点からなる三角形の内部にあるかどうか」を判定するアルゴリズム**を実装することです。

#### 1. Point クラスの作成
まず、2D平面上の点を表す `Point` クラスを作成します。これも当然 **Orthodox Canonical Form** で作成します。
*   **メンバ変数**:
    *   `Fixed const x;`
    *   `Fixed const y;`
    *   ※ここでのポイントは `const` がつ与えられていることです。一度座標を決めたら変更できない仕様にする必要があります。

#### 2. bsp 関数の実装
次に、以下の関数を実装します。
```cpp
bool bsp( Point const a, Point const b, Point const c, Point const point);
```
*   `a`, `b`, `c`: 三角形の3つの頂点。
*   `point`: 判定したい点。
*   戻り値: 点が三角形の**完全に内部**にあれば `true`、外側や**辺・頂点の上**にあれば `false`。

#### 3. 数学的なアプローチ（外積を利用した判定）
この問題は、ベクトルの「外積（Cross Product）」を使うと美しく解けます。



点 `P` が三角形 `ABC` の内部にあるための条件は、
*   辺 `AB` から見て `P` が同じ側にある。
*   辺 `BC` から見て `P` が同じ側にある。
*   辺 `CA` から見て `P` が同じ側にある。

具体的には、外積 $\vec{AB} \times \vec{AP}$、$\vec{BC} \times \vec{BP}$、$\vec{CA} \times \vec{CP}$ を計算し、**これら3つの外積の符号（プラスかマイナスか）が全て一致**していれば、点は三角形の内部にあると判定できます。
（1つでも `0` になれば、それは辺の上にあることを意味するので `false` とします）。

**STL（Standard Template Library）とは** 
C++の標準ライブラリの一部であり、「データを効率よく管理・操作するための、超便利な汎用テンプレート部品箱」のことです。

### STLを構成する3大要素

STLは、主に以下の3つの要素が連携して動くように設計されています。これらは「cpp08.pdf」におけるModule 08の学習テーマそのものです。

* **Containers（コンテナ）**
データを格納するためのデータ構造です。代表的なものとして `vector`、`list`、`map` などが用意されています。用途に応じて最適な箱を選ぶことができます。


* **Algorithms（アルゴリズム）**
データの検索、並べ替え、集計などを行う共通の関数群です。`<algorithm>` ヘッダ内に定義されています。


* **Iterators（イテレータ）**
コンテナ内の要素を順番に指し示す「高度なポインタ」です。コンテナ（箱）とアルゴリズム（処理）を繋ぐ橋渡し役を担います。



### STLの何がすごいのか？

最大のメリットは「コンテナの種類に依存せずに、同じアルゴリズムを使い回せること」です。

例えば、`std::find` という1つの検索アルゴリズムがあるだけで、イテレータを介すことで `vector` からでも `list` からでも全く同じコードでデータを検索できます。プログラマがいちいちデータ構造ごとに検索用の `for` ループを書く必要がなくなります。


**コンテナ (Container) とは**

コンテナは、複数のデータをひとまとめに格納・管理するためのデータ構造（クラス）です。
従来のC言語で使っていた配列を、より安全で多機能にしたものだと考えてください。フィードバックで触れられていた **RAII（Resource Acquisition Is Initialization）** の恩恵を最も受けている機能の一つであり、データの追加や削除に伴うメモリの動的確保・解放を、コンテナ自身のコンストラクタとデストラクタが自動で行ってくれます。

* **`std::vector`**: 動的配列。要素を追加していくと自動でメモリ領域を拡張します。データがメモリ上で連続しているため、インデックス（`vec[3]` など）を使ったアクセスが非常に高速です。
* **`std::list`**: 双方向連結リスト。データがメモリ上のバラバラな場所に配置されますが、要素の途中への挿入や削除が高速です。
* **`std::map`**: キーと値のペアを保存する連想配列。検索機能に優れています。

コンテナとは、どんなデータ型でも格納できるように設計されたクラス（クラステンプレート）のことで、vector や list などがそれに該当する。
これらに対して検索などの共通処理を行いたい時に、<algorithm> をインクルードして使う。

---

**イテレータ (Iterator) とは**

イテレータは、コンテナの中身を順番に指し示し、操作するための「高度なポインタ」**です。
`vector`（連続したメモリ）や `list`（分断されたメモリ）など、コンテナごとに内部の構造は全く異なります。イテレータはそれらの内部構造の違いを吸収し、**「どんなコンテナであっても同じ構文でデータを巡回できるようにする」という重要な役割を持っています。

* **ポインタと同じ操作感**: `*it` で現在指しているデータの中身を取得し、`++it` で次の要素へ進みます。
* **共通の境界**: すべてのイテラブルなコンテナは、先頭を指す `begin()` と、最後の要素の「一つ次（終端）」を指す `end()` を提供します。

このイテレータの仕組みがあるおかげで、`<algorithm>` ヘッダにある `std::find` や `std::sort` は、相手がどんなコンテナであるかを気にせず、共通の手順で処理を行うことができます。Exercise 02の `MutantStack` は、本来イテレータを持たない `std::stack` にこの巡回機能を追加し、他のコンテナと同じように扱えるようにする課題でした。

<h2><span style="color:pink;">
例外指定について
</span></h2>

```cpp
virtual const char* what() const throw() {
```

この一行は、C++の標準例外クラス std::exception のメソッドをオーバーライド（上書き）するための宣言です。C++98規格に基づく厳密な意味を持っています。

**virtual**: 仮想関数であることを示します。これを付けることで、基底クラス（std::exception）のポインタや参照経由で呼び出された場合でも、この派生クラス（NotFoundException）の実装が正しく実行されます（ポリモーフィズム）。

**const char***: 関数の戻り値の型です。書き換え不可能な文字配列（C言語スタイルの文字列）の先頭アドレスを返します。

**what()**: 関数名です。例外の内容を文字列で返す役割を持ちます。

**const** (1つ目): このメンバ関数が、属しているオブジェクト（例外オブジェクト自体）のメンバ変数を一切書き換えないことを保証します。

**throw()**: 例外指定（Exception Specification）と呼ばれるC++98特有の構文です。括弧の中が空であるため、「この関数自体は内部で絶対に例外を投げない」ということをコンパイラに約束しています。

### ○ throw(): 例外指定はなんのために必要なのか？

最大の理由は、親クラス（std::exception）のルールに一致させるためです。

親クラスである std::exception の what() 関数は、C++98規格において virtual const char* what() const throw(); と定義されています。C++のルールでは、親の関数を子クラスで上書き（オーバーライド）する際、「親が約束している例外の厳しさ」と同じか、それ以上に厳しくしなければならないという決まりがあります。

親の what() が「私は絶対に別の例外を投げない（throw()）」と約束しているため、子クラスの what() も同じように throw() をつけて約束を守らないと、コンパイルエラーになってしまいます。また、「エラーを報告するための処理（what()）の最中に、さらに別のエラーが発生してしまう」というプログラムの致命的なパニック（強制終了）を防ぐという重要な安全上の意味もあります。

### ○ 例外指定をしないで、throwを投げる場合の書き方

結論から言うと、関数の後ろに何も書かない（例外指定を全くつけない） だけで、自由に例外を投げることができます。

C++98における例外指定のルールは以下のようになっています。

C++
// 1. 例外指定なし（デフォルト）
// どんな種類の例外でも投げることができる
void doSomething() {
    throw std::exception();
}

// 2. 空の例外指定
// 「この関数は絶対に例外を投げない」というコンパイラへの約束
void doNothing() throw() {
    // ここでthrowすると、プログラムが強制終了(std::terminate)する危険があります
}

// 3. 特定の例外指定
// 「この関数は NotFoundException しか投げない」という約束
void findSomething() throw(NotFoundException) {
    throw NotFoundException();
}
先ほどの what() 関数の場合は、親クラスである std::exception 側で virtual const char* what() const throw(); と「絶対に例外を投げない」と固く約束されていたため、子クラスでもそれに合わせて throw() を書く必要がありました。

しかし、ご自身で新しく作る関数（親クラスの制約を受けない関数）の中で例外を投げたい場合は、単に void myFunction() { throw MyException(); } のように、何も指定せずに書くのが一般的であり、最も正しい書き方です。

### 1. `easyfind.hpp` の処理内容

このファイルでは、どのようなコンテナ（配列のようなデータ構造）が来ても共通の手順で検索を行える「テンプレート関数」を定義しています。

* **例外クラスの定義 (`NotFoundException`)**
標準ライブラリの `std::exception` を継承し、独自のエラークラスを作っています。値が見つからなかった際に返すエラーメッセージを `what()` 関数の中に定義しています。
* **検索関数 `easyfind` の本体**
型 `T`（vectorやlistなどのコンテナ型）を受け取るテンプレート関数です。
1. **`std::find` による検索**: `<algorithm>` ヘッダに含まれるこの機能は、`container.begin()`（先頭）から `container.end()`（終端）までを順番に調べ、探している `value` が見つかればその場所（イテレータ）を返します。
2. **終端（見つからなかった場合）の判定**: もし `it == container.end()` となった場合、それは「コンテナの最後まで探したが、値が存在しなかった」ことを意味します。この時、先ほど作った `NotFoundException` を `throw` して処理を中断し、エラーを知らせます。
3. **成功時の返却**: 見つかった場合は、その場所を示すイテレータ `it` をそのまま返します。


* **const用のオーバーロード（関数定義）**
非const版と全く同じロジックですが、引数に `const T&` を受け取り `const_iterator` を返します。これにより、読み取り専用（変更不可）のコンテナが渡された場合でもエラーにならず、安全に検索を行えるようになっています。

### 2. `main.cpp` の処理内容

このファイルでは、作成した `easyfind` 関数が正しく動くかどうかを `std::vector` と `std::list` の2種類のコンテナを使ってテストしています。

* **コンテナの準備とRAII**
`std::vector<int> vec;` や `std::list<int> lst;` としてコンテナを宣言し、数値を詰めています。ここで、いただいたフィードバックにある **RAII（Resource Acquisition Is Initialization）** が活躍しています。これらのコンテナは作成時に自動でメモリを確保し、`main` 関数が終了してスコープを抜ける際に自動でデストラクタが呼ばれ、安全にメモリを解放します。そのため、手動での後片付けが不要になっています。
* **正常系のテスト（存在する値の検索）**
`easyfind(vec, 20)` のようにコンテナ内に確実に存在する値を渡し、返ってきたイテレータの中身（`*it`）を `cout` で出力しています。
* **異常系のテスト（存在しない値の検索）と例外処理**
`easyfind(vec, 42)` のようにコンテナ内にない値を検索しています。この時、`easyfind` の内部で `NotFoundException` が投げられますが、`try { ... } catch (...)` ブロックで囲んでいるため、プログラムが強制終了（クラッシュ）することはありません。
`catch (const std::exception& e)` の部分でエラーを安全に捕まえ、`e.what()` を呼び出して "Error: Element not found in the container." というメッセージを出力して正常に処理を続けています。


### 3. T::iterator の意味
T はテンプレートで受け取った「コンテナの型」（例: std::vector<int> や std::list<int>）を指します。::（スコープ解決演算子）を使って、そのコンテナクラスの内部で定義されている iterator という型（ネストされた型）を指定しています。つまり、T::iterator は 「渡されたコンテナ専用のイテレータ型」 という意味になります。なお、テンプレート内でこのように依存名（コンテナに依存する型）を使う場合は、コンパイラに「これは変数ではなく型である」と教えるために、直前に typename を付けるのがC++の文法ルールです。

### 4. std::find の動き
<algorithm> ヘッダに含まれる std::find は、以下のような動きで検索を行います。  
- 第1引数のイテレータ（begin）が指す場所からスタートします。
- 第2引数のイテレータ（end）が指す場所の手前まで、順番に要素を確認して進みます。
- 現在の要素と、第3引数で渡された値（value）を == 演算子で比較します。
- 一致する要素が見つかった瞬間に検索を終了し、その場所を指すイテレータを返します。
- 最後まで見つからなかった場合は、第2引数で渡された「終端を示すイテレータ」をそのまま返します。

### 5. it == container.end() だけで「見つからなかった」と判定できる理由
C++のSTLコンテナにおいて、end() は「最後の要素」を指しているのではなく、「最後の要素の1つ次（メモリの境界外）」 を指しています。std::find は、要素が見つからずに最後まで探索し切ると、この「1つ次」である end() のイテレータを返して終了する仕様になっています。そのため、返ってきたイテレータ it が container.end() と一致するかどうかを見るだけで、コンテナ内に値が存在しなかったことを確実に判定できます。

### 6. *it1 のようにイテレータがポインタ型のように扱える理由
イテレータは、コンテナの要素を指し示すための「高度なポインタ（スマートポインタの一種）」として設計されているためです。イテレータの実体は単なるメモリアドレスではなく、コンテナ内で定義されたクラスのオブジェクトです。しかし、このクラスの内部で * 演算子（間接参照演算子）がオーバーロード（上書き定義） されています。これにより、プログラマは内部の複雑なデータ構造（連続した配列か、バラバラなリストか）を一切気にすることなく、C言語のポインタと全く同じように *it1 と書くだけで、現在指している場所のデータの中身を取り出せるようになっています。

### なぜ `std::stack` はイテレータを持たないのか？

少しだけ背景を補足します。`std::stack` は本来、「最後に入れたものを、最初に取り出す（LIFO: Last In, First Out）」という厳密なルールを守るためのデータ構造です。途中のデータを覗き見たり、順番にアクセスしたりできてしまうと、その前提が崩れてしまうため、あえてイテレータが封印されています。

しかしこの課題では、「あえてそのルールをぶち壊して（butchering the original stack）、足りない機能を追加してみよう」という、少し過激で実践的なC++のハッキング（クラスの継承と内部構造の公開）を学ぶことがテーマとなっています。

### 1. テンプレート宣言の解説

```cpp
template <typename T, typename Container = std::deque<T> >

```

これは `MutantStack` を「どんなデータ型」でも「どんな内部構造」でも使えるようにするための宣言です。

* **`typename T`**: スタックに格納する中身のデータ型です（例：`int` や `std::string`）。
* **`typename Container = std::deque<T>`**: スタックの裏側で実際にデータを保存する「土台となるコンテナ」を指定します。`=` 以降はデフォルト引数と呼ばれ、「もし使う人が何も指定しなかったら、デフォルトで `std::deque`（両端キュー）を使いますよ」という意味になります。これは標準の `std::stack` と全く同じ仕様です。

### 2. 4つの `typedef` とイテレータの解説

`typedef` は、長くて複雑な型の名前に「短い別名（エイリアス）」をつけるためのC++の機能です。ここでは、土台となる `Container` の中に定義されている各種イテレータを、外部から使いやすいように再定義しています。

* **`iterator`**:
`typedef typename Container::iterator iterator;`
通常のイテレータです。先頭から末尾に向かって進み、指している要素の値を読み取ることも、書き換えることもできます。
* **`const_iterator`**:
`typedef typename Container::const_iterator const_iterator;`
読み取り専用のイテレータです。データを順番に見ることはできますが、安全のために値を書き換えることはコンパイラによって禁止されます。
* **`reverse_iterator`**:
`typedef typename Container::reverse_iterator reverse_iterator;`
逆順イテレータです。末尾から先頭に向かって（逆方向に）進みます。値の読み書きが可能です。
* **`const_reverse_iterator`**:
`typedef typename Container::const_reverse_iterator const_reverse_iterator;`
読み取り専用の逆順イテレータです。逆方向に進みますが、値の書き換えはできません。

これら4種類をすべて用意することで、他の標準コンテナ（`std::list` や `std::vector` など）と完全に同じインターフェースを持つ本格的なコンテナとして機能するようになります。

### 1. `std::deque` とは？

`std::deque`（デック：Double Ended Queueの略）は、「両端キュー」と呼ばれるSTLコンテナの一つです。

* `vector` は「末尾」への追加が速いですが、先頭への追加は遅いです。
* `deque` は「先頭」と「末尾」の両方に対して、高速にデータを追加・削除できる構造になっています。
`std::stack` はデフォルトでこの `deque` を裏側のデータ保存用コンテナとして採用しています。

### 2. `typename` による型の自由度

ご認識の通りです！
`template <typename T>` と宣言することで、「このクラスは `int` でも `std::string` でも、好きな型を `T` に当てはめて自由に使っていいですよ」という汎用的な設計図になります。これがテンプレートの最大の強みです。

### 3. `typedef` と `typename` の違い

ここでは2つのキーワードが組み合わせて使われていますが、役割は全く異なります。

* **`typedef`**: 既存の長い型名に「短いあだ名（エイリアス）」をつける機能です。
* **`typename`**: テンプレートの中で「これは変数ではなく『型』の名前ですよ」とコンパイラに教えるためのキーワードです。コンパイラが誤読するのを防ぐために必須となります。

### 4. 4つの `typedef` は省略可能か？

実は、単にイテレータを返すだけなら「めんどくさいから書いている」という側面もあり、省略して以下のように直接書くことも可能です。

```cpp
typename Container::iterator begin() { return this->c.begin(); }

```

しかし、C++の標準的なコンテナ（`vector` や `list` など）は、クラスの内部で必ず `iterator` という短い名前の型を定義するルール（慣習）を持っています。今回 `typedef` を書いたのは、**他の標準コンテナと全く同じ顔（インターフェース）を持たせることで、どんなSTLアルゴリズムからも正しく扱えるようにするため**という重要な意味があります。

### 1. `vector` と `deque` の構造について

結論から言うと、**どちらも双方向リスト（Doubly Linked List）ではありません。**

* **`std::vector`**: メモリ上に一直線にデータが隙間なく並ぶ「動的配列」です。
* **`std::deque`**: 複数の小さな固定長の配列をブロック状に繋ぎ合わせた「両端キュー」です。
* **双方向リスト**: C++のSTLにおいて双方向リストに該当するのは **`std::list`** です。

「cpp08.pdf」のテストコードにおいて `MutantStack` と `std::list` の結果を比較させているのは、「裏側が配列（deque）であっても、リスト（list）であっても、イテレータという共通の道具を使えば全く同じように扱える」というSTLの強力なメリットを証明するためです。

### 2. `typedef` の詳細

`typedef`（Type Definition）は、すでに存在する型に対して「新しい別名」をつけるための機能です。

* **目的**: 特にテンプレートを使用すると型名が非常に長く複雑になるため、それを短く直感的な名前に置き換えてコードの可読性を高めます。
* **規格の遵守**: 「cpp08.pdf」では `C++98` 規格への準拠が義務付けられています。新しいC++規格では `using` という別の書き方もありますが、C++98においては `typedef` を使用するのが正しいエイリアスの作成方法です。

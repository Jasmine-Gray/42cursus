# C++ Module 07


<h2><span style="color:pink;">
Templates（テンプレート）について
</span></h2>


C++のテンプレートは、「型（Type）に依存しない汎用的なコード」を書くための強力な機能です。通常、C++では関数やクラスを定義する際に引数や戻り値の「型」を明記する必要がありますが、テンプレートを使うことで、コンパイル時にあらゆる型に対応できる「ひな形（テンプレート）」を作成することができます。

Module 07では、このテンプレート機能を以下の2つのアプローチで学びます。

#### 1. 関数テンプレート (Function Templates)

関数テンプレートは、異なるデータ型に対して同じ処理を行う関数を一つにまとめる機能です。

* **ex00 (Start with a few functions):**
任意の型を受け取ることができる `swap`, `min`, `max` という関数テンプレートを実装します。これらの関数は、渡される2つの引数が同じ型であり、かつ比較演算子をサポートしているという条件さえ満たせば、どのような型の引数でも呼び出すことができます。また、テンプレート関数の定義はヘッダファイル内で行う必要があります。


* **ex01 (Iter):**
配列のアドレス、配列の長さ、そして配列の各要素に対して呼び出される関数を引数に取る `iter` という関数テンプレートを実装します。これも、あらゆる型の配列に対して動作しなければなりません。



#### 2. クラステンプレート (Class Templates)

クラステンプレートは、クラスのメンバ変数やメソッドの型を汎用化する機能です。C++の標準ライブラリ（`std::vector` や `std::string` など）もこの技術で作られています。

* **ex02 (Array):**
型 `T` の要素を格納できる `Array` というクラステンプレートを開発します。


* メモリの割り当てには必ず `new[]` 演算子を使用しなければなりません。


* クラスのコンストラクタでメモリを確保し、デストラクタで確実に解放することで、メモリリークを防ぐ堅牢な設計（RAII）が求められます。


* また、`[]` 演算子を使用して要素にアクセスする際、インデックスが範囲外の場合は `std::exception` をスローする必要があります。





C++のテンプレートは非常に強力ですが、コンパイル時に型推論とコード生成が行われるため、実装はヘッダファイル（`.hpp` や `.tpp`）に記述するのが一般的であるという特徴を持っています。

<h2><span style="color:pink;">
ex00: Start with a few functions
</span></h2>

この課題の目的は、C++の「関数テンプレート」の基本的な書き方を学び、型に依存しない汎用的な関数を実装することです。Subjectのルール通り、テンプレートの定義はすべてヘッダファイル（`whatever.hpp`）内に記述されています。

#### 1. `swap` 関数テンプレート

```cpp
template <typename T>
void swap(T& a, T& b) {
    T temp = a;
    a = b;
    b = temp;
}

```

* **要件**: 2つの引数の値を入れ替え、何も返さないこと。


* **解説**: `template <typename T>`とすることで、`int`や`std::string`など、同じ型`T`を持つ2つの引数を受け取ることができます。参照渡し（`T&`）を使用しているため、関数内で書き換えた値が呼び出し元に正しく反映されます。



#### 2. `min` 関数テンプレート

```cpp
template <typename T>
const T& min(const T& a, const T& b) {
    // b が a 以下（等しい場合を含む）であれば2つ目の引数 b を返す
    return (b <= a) ? b : a;
}

```

* **要件**: 2つの値を比較して小さい方を返すこと。**値が等しい場合は、2つ目の引数を返すこと**。


* **解説**: ここがこの関数の最も重要なポイントです。三項演算子で `(b <= a)` と条件を指定することで、`b`（2つ目の引数）が `a`（1つ目の引数）と等しい場合に `true` となり、確実に2つ目の引数である `b` が返されるようになっています。また、引数と戻り値を `const T&`（const参照）にすることで、オブジェクトの無駄なコピーを防いでいます。

#### 3. `max` 関数テンプレート

```cpp
template <typename T>
const T& max(const T& a, const T& b) {
    // b が a 以上（等しい場合を含む）であれば2つ目の引数 b を返す
    return (b >= a) ? b : a;
}

```

* **要件**: 2つの値を比較して大きい方を返すこと。**値が等しい場合は、2つ目の引数を返すこと**。


* **解説**: `min` 関数と同様に、等しい場合の条件をクリアするために `(b >= a)` という判定を行っています。これにより、値が等しい時は2つ目の引数 `b` が返却されます。すべての比較演算子（この場合は `>=`）をサポートしている型であれば、どのような型でも処理できます。

---

### 1. `template <typename T>` は毎回一番上に入れる

テンプレート関数やテンプレートクラスを定義・宣言する際、C++コンパイラに対して「これから書く関数（またはクラス）は、`T`という仮の型を使ったテンプレートですよ」と毎回教えてあげる必要があるためです。

```cpp
// 1つ目の関数
template <typename T>
void swap(T& a, T& b) { ... }

// 2つ目の関数（ここでも再度記述が必要）
template <typename T>
const T& min(const T& a, const T& b) { ... }

```

もし2つ目の関数で `template <typename T>` を書き忘れると、コンパイラは「`T`って何の型？そんな型は知らない」とエラーを出してしまいます。そのため、関数やクラスごとに独立して宣言する必要があります。

### 2. 「const参照渡しによるオーバーヘッド」とは何か？

まず「オーバーヘッド（overhead）」とは、コンピュータ処理における「余分な負荷（処理時間やメモリの消費）」のことを指します。

実は、正確に言うと「const参照渡し」は**オーバーヘッドを防ぐため**に使われます。対極にある「値渡し（Pass by value）」と比較すると分かりやすいです。

**値渡し（コピーが発生する = オーバーヘッドが大きい）**

```cpp
void printString(std::string s) { ... }

```

引数をそのまま渡すと、関数が呼び出されるたびに `std::string` の中身（文字列データ全体）が新しくメモリ上にコピーされます。数文字なら良いですが、数百万文字のテキストデータだった場合、コピーするだけで膨大な時間とメモリ（＝大きなオーバーヘッド）がかかってしまいます。

**参照渡し（コピーが発生しない = オーバーヘッドがない）**

```cpp
void printString(std::string& s) { ... }

```

参照渡し（`&`）にすると、コピーを作るのではなく「データがある場所（アドレス）」だけを関数に伝えます。どれだけ巨大なデータでも、渡すのは場所の情報だけなので一瞬で終わります。

**const参照渡し（安全で高速）**

```cpp
void printString(const std::string& s) { ... }

```

参照渡しは高速ですが、関数内で元のデータを書き換えられてしまう危険性があります。そこで `const` をつけることで、「高速な参照渡しをするけれど、絶対に中身は変更しない（読み取り専用）」という安全な渡し方ができます。

このため、C++（特にテンプレートなどでどんな巨大な型が来るか分からない場合）では、コピーのオーバーヘッドを防ぐために `const T&` を使うのが基本のベストプラクティスとなります。

<h2><span style="color:pink;">
ex01: Iter 
</span></h2>

この課題の目的は、**任意の型の配列に対し、指定した関数を各要素に適用する関数テンプレート `iter` を実装すること**です。C++標準ライブラリの `std::for_each` のような動きをするものを自作します。

#### 1. 引数の仕様

`iter` 関数テンプレートは、以下の3つの引数を受け取ります。

1. **配列のアドレス**: 任意の型の配列のポインタ（`T*`）。
2. **配列の長さ**: `const` 値として渡される長さ（例: `const std::size_t`）。
3. **適用する関数**: 配列の各要素に対して呼び出される関数、またはインスタンス化された関数テンプレート。

#### 2. 最大のポイント: `const` と非 `const` の両立

Subjectに以下のように書かれています。

> "The function passed as the third parameter may take its argument by const reference or non-const reference, depending on the context. Think carefully about how to support both const and non-const elements in your iter function."

これがこの課題の「罠」であり、最も考えるべき点です。
配列には「書き換え可能な通常の配列」と「読み取り専用の `const` 配列」があります。

* 通常の配列を渡した場合、第3引数の関数は「要素を書き換える関数（非 `const` 参照受け取り）」でも「読み取るだけの関数（`const` 参照受け取り）」でも動作しなければなりません。
* `const` 配列を渡した場合、第3引数の関数は「読み取るだけの関数（`const` 参照受け取り）」でなければならず、要素を書き換えようとする関数を渡すとコンパイルエラーになるのが正しい挙動です。

#### 3. 実装のアプローチ

この両方（`const`な要素と非`const`な要素）を安全にサポートするために、テンプレートの型推論を利用します。一般的には、第3引数の関数もテンプレートパラメータとして受け取るように設計し、必要に応じて `iter` 関数自体を `T*` 用と `const T*` 用でオーバーロードする（または `T` そのものに `const` を推論させる）アプローチを取ります。

---
どのように、`const`と非`const`を分けたのか？

C++の「関数テンプレートのオーバーロード（多重定義）」という仕組みを利用して分けました。

Module 07のSubjectには、`iter`関数において「constな要素と非constな要素の両方をサポートする方法を慎重に考えること」という明確な指示があります。これを実現するために、引数の型（シグネチャ）だけを変えた2つの `iter` 関数を用意しました。

```cpp
// ① 非const配列を受け取るバージョン
template <typename T, typename Func>
void iter(T* array, const std::size_t length, Func func) {
    for (std::size_t i = 0; i < length; ++i) {
        func(array[i]);
    }
}

// ② const配列を受け取るバージョン
template <typename T, typename Func>
void iter(const T* array, const std::size_t length, Func func) {
    for (std::size_t i = 0; i < length; ++i) {
        func(array[i]);
    }
}

```

この2つを定義しておくことで、コンパイラが以下の仕組みで自動的に判断してくれます。

* **非const配列を渡した場合**
通常の配列（例: `int intArray[] = {1, 2, 3};`）を `iter` に渡すと、C++コンパイラは完全に一致する **①の `T* array**` のバージョンを自動的に選択します。これにより、第3引数で渡した関数が配列の要素を書き換える（非const参照として扱う）ことが可能になります。
* **const配列を渡した場合**
`const` がついた配列（例: `const int constIntArray[] = {1, 2, 3};`）を `iter` に渡すと、コンパイラは `const` を維持できる **②の `const T* array**` のバージョンを選択します。これにより、関数内でも配列の要素は読み取り専用として扱われ、誤って値を変更しようとする関数を渡すとコンパイルエラーで弾いてくれます。

### なぜこの方法が必要なのか？

仮に、どちらか1つのテンプレートしか用意しなかった場合、以下の問題が発生します。

* **`T* array` だけの場合**: `const` 配列を渡したとき、「`const` を勝手に外してはいけない」というC++のルールに違反し、コンパイルエラーになります。
* **`const T* array` だけの場合**: 通常の配列を渡したとき、コンパイラは暗黙的に `const` を付与して受け取ってくれますが、関数内で要素の値を書き換えることが一切できなくなってしまいます。

このように2つのバージョンを明示的に用意（オーバーロード）することで、C++のコンパイラが渡された配列の `const` 性に応じて適切な方を自動選択し、Subjectの要求を満たす設計にしています。

### 1. `iter.hpp` の解説（テンプレート関数の設計）

#### テンプレートのオーバーロード（const と 非const の分離）

```cpp
// ① 非const配列用の iter
template <typename T, typename Func>
void iter(T* array, const std::size_t length, Func func) { ... }

// ② const配列用の iter
template <typename T, typename Func>
void iter(const T* array, const std::size_t length, Func func) { ... }

```

* **引数の仕様準拠**: Subjectの指定通り、第1引数に配列のアドレス、第2引数に配列の長さ（`const` 値として）、第3引数に関数を受け取っています。


* **const / non-const の両立**: 同じ `iter` という名前の関数を2つ定義し、第1引数を `T*`（書き換え可能な配列）と `const T*`（読み取り専用の配列）で分けています。これにより、呼び出し元が渡した配列が `const` かどうかに応じて、コンパイラが自動的に正しい方の関数を選んでくれます。

#### テンプレート引数 `Func` の採用

```cpp
template <typename T, typename Func>

```

* **インスタンス化された関数テンプレートへの対応**: Subjectには「第3引数として渡される関数は、インスタンス化された関数テンプレートでもよい」と記載されています。


* 第3引数を明確な関数ポインタ（例: `void (*func)(T&)`）に固定してしまうと、コンパイラによってはテンプレート関数の解決がうまくできないことがあります。引数自体を `Func` というテンプレートにすることで、通常の関数、関数テンプレート、さらには関数オブジェクト（ファンクタ）まで、あらゆる「呼び出し可能なもの（Callable）」を柔軟に受け取れる堅牢な設計になっています。

### 2. `main.cpp` の解説（テストによる挙動の証明）

`main.cpp` では、実装した `iter` 関数があらゆる型とコンテキスト（const/非const）で動作することを、テストを通して証明しています。

#### テスト用の関数群

```cpp
template <typename T> void printElement(T& elem);
template <typename T> void printConstElement(const T& elem);
void increment(int& n);

```

* **`printElement` / `printConstElement**`: Subjectの「第3引数にはインスタンス化された関数テンプレートを渡せる」という要件をテストするための関数です。


* **`increment`**: 値を書き換える（非const参照を要求する）通常の関数です。

#### テスト1＆2: 非const配列の処理

```cpp
int intArray[] = {1, 2, 3, 4, 5};
::iter(intArray, 5, printElement<int>);
::iter(intArray, 5, increment);

```

* `intArray` は非const（書き換え可能）な配列です。
* ここには、値を読み取るだけの関数（`printElement`）も、値を書き換える関数（`increment`）も、問題なく適用できます。

#### テスト3: const配列の保護（ここが最も重要です）

```cpp
const int constIntArray[] = {10, 20, 30, 40, 50};
// ::iter(constIntArray, 5, increment); // コンパイルエラーになるのが正しい挙動
::iter(constIntArray, 5, printConstElement<int>);

```

* `constIntArray` は `const`（読み取り専用）な配列です。
* コメントアウトされている `increment` を適用しようとすると、配列の要素を変更しようとするため**コンパイルエラー**になります。これは、`iter.hpp` で `const T*` 用のオーバーロードが正しく機能し、「読み取り専用の配列を安全に守っている（型安全性が保たれている）」ことの証明になります。



#### テスト4: 任意の型への対応

```cpp
std::string strArray[] = {"Hello", "42", "World"};
::iter(strArray, 3, printConstElement<std::string>);

```

* Subjectの「どのような型の配列でも動作しなければならない」という要件 を満たすため、組み込み型（`int`）だけでなくクラス型（`std::string`）の配列でもテストを行い、問題なく動作することを示しています。

<h2><span style="color:pink;">
ex02: Array 
</span></h2>

この課題の目的は、任意の型 `T` の要素を格納できる、安全で再利用可能な配列クラステンプレート `Array` を作成することです。C++標準ライブラリのコンテナ（`std::vector` など）の基礎的な仕組みを自作することで、テンプレートと動的メモリ管理の理解を深めます。

### 1. テンプレートクラスの定義

* 任意の型の要素を格納できるクラステンプレート `Array` を開発します。



### 2. コンストラクタと初期化（Orthodox Canonical Form）

* **引数なしのコンストラクタ**: 空の配列を作成します。


* **`unsigned int n` を引数に取るコンストラクタ**: デフォルト初期化された `n` 個の要素を持つ配列を作成します。


* *ヒント*: `int * a = new int();` のように記述することで、組み込み型（`int`など）であっても未初期化のガベージ値ではなく `0` で安全に初期化される仕組みを利用します。




* **コピーコンストラクタと代入演算子**: コピーによる構築と代入を実装します。


* コピー後、元の配列またはコピー先の配列のどちらかを変更しても、もう一方の配列に影響を与えてはなりません（完全なディープコピーの必須要件です）。





### 3. メモリ管理（RAIIの徹底）

* メモリの確保には必ず `new[]` 演算子を使用しなければなりません。


* 事前にメモリを割り当てること（Preventive allocation）は禁止されています。


* プログラムは決して未割り当てのメモリにアクセスしてはなりません。


* *フィードバックの適用*: コンストラクタでリソース（メモリ）を獲得し、デストラクタで確実に解放（`delete[]`）するRAIIの原則に則った設計にします。



### 4. 要素へのアクセスと例外処理

* 添字演算子 `[ ]` を介して要素にアクセスできるようにオーバーロードします。


* アクセス時のインデックスが範囲外（out of bounds）の場合、`std::exception` をスローしなければなりません。


* ※constな配列からも読み取りができるように、`const` 用と非 `const` 用の2つの `operator[]` を用意するのがベストプラクティスです。



### 5. 要素数の取得

* 配列内の要素数を返すメンバ関数 `size()` を実装します。


* このメンバ関数は引数を取らず、現在のインスタンスを変更してはならないため、`const` メンバ関数として定義する必要があります。

## 1. `Array.hpp` (クラステンプレートの宣言)

このファイルは、`Array` クラスの「設計図」です。どのような型のデータでも扱えるように、**クラステンプレート**として定義されています。

* **テンプレート宣言 (`template <typename T>`)**:
これをつけることで、`int` や `std::string` など、任意の型 `T` を格納できる汎用的な配列クラスになります。
* **Orthodox Canonical Form (正統派カノニカルフォーム)**:
C++98におけるクラス設計の基本である、デフォルトコンストラクタ、コピーコンストラクタ、代入演算子、デストラクタの4つがしっかりと宣言されています。
* **例外クラス (`OutOfBoundsException`)**:
クラスの内部に例外用のクラスを定義しています。`std::exception` を継承し、後で範囲外アクセスがあった際にスローするためのものです。

---

## 2. `Array.tpp` (クラステンプレートの実装)

このファイルには、クラスの実際の処理（メソッドの中身）が書かれています。ここでは特にRAII（リソース獲得は初期化である）の概念と、**ディープコピー**が重要になります。

### RAIIとメモリ管理 (コンストラクタとデストラクタ)

* **引数付きコンストラクタ**:
`elements(new T[n]())` と記述されています。ここで `new[]` を使ってメモリを動的に確保しています。Subjectのヒントにある通り、末尾に `()` をつけることで、組み込み型（`int`など）であっても確実に `0` で初期化される安全な設計です。
* **デストラクタ (`~Array`)**:
`delete[] this->elements;` が呼ばれます。コンストラクタで確保したメモリを、オブジェクトの寿命が尽きた瞬間に**自動的かつ確実**に解放します。これがRAIIの真髄であり、手動で解放用の関数を呼ぶ必要がないためメモリリークを防ぎます。

### ディープコピー (コピーコンストラクタと代入演算子)

* 単なるポインタのコピー（浅いコピー / Shallow Copy）ではなく、新しいメモリを確保して中身の値を一つずつ写し取る深いコピー（Deep Copy）を行っています。
* **代入演算子 (`operator=`)**:
自己代入（自分自身への代入 `a = a`）を `if (this != &other)` で防ぎつつ、コピー前に `delete[] this->elements;` で**既存のメモリを一度解放**しています。これもRAIIに基づく非常に重要なエラー防止策です。

### 要素への安全なアクセス (`operator[]`)

* `index >= this->length` で境界チェックを行っています。もし配列のサイズを超えたインデックスにアクセスしようとした場合、プログラムをクラッシュさせるのではなく `throw OutOfBoundsException();` で例外を投げます。これにより、呼び出し側で安全にエラーハンドリングができるようになります。

### 1. `.tpp` ファイルとは何か？

`.tpp` はテンプレート実装ファイル（Template Implementation File）と呼ばれるものです。

* **役割**: テンプレートクラスやテンプレート関数の「実装部分（中身）」を記述するためのファイルです。
* **なぜ必要なのか**: 通常のC++クラスでは、宣言を`.hpp`に、実装を`.cpp`に分けますが、**テンプレートの場合はコンパイルの仕組み上、コンパイラが宣言と実装を同時に見れる状態にしておく必要があります。** そのため、実装もヘッダファイル内に書くのが一般的です。しかし、すべてを`.hpp`に書くとコードが長くなり可読性が下がるため、実装部分だけを`.tpp`（または`.tcc`, `.inl`など）に切り出し、`.hpp`の一番下で `#include "Array.tpp"` のように読み込む手法がとられます。

### 2. 組み込み型（Built-in type）とは何か？

組み込み型とは、**C++という言語そのものに最初から用意されている基本的なデータ型**のことです（プリミティブ型とも呼ばれます）。

* 例: `int`, `char`, `float`, `double`, `bool` など。
* これらは `class` や `struct` を使ってユーザーが定義したものではなく、メモリ上のサイズや振る舞いがコンパイラによって直接定められています。

### 3. 何をしたらディープコピー（Deep Copy）になるのか？

ディープコピーにするためには、以下の2つを確実に行う必要があります。

1. **新しいメモリ領域を動的に確保する**（例: `new T[size]`）。
2. 確保した新しいメモリ領域に、**コピー元の「実体の値」をループなどを回して一つずつコピーする**。

### 4. ディープコピー（Deep Copy）についての詳細

ディープコピーを理解するには、対義語であるシャローコピー（Shallow Copy = 浅いコピー）と比較するのが一番分かりやすいです。

* **シャローコピー（危険）**:
ポインタ（メモリアドレス）だけをコピーします。コピー元とコピー先が**全く同じメモリ空間を共有**してしまうため、一方の値を変更するともう一方も変わってしまいます。また、デストラクタが呼ばれた際に、同じメモリを2回解放しようとしてプログラムがクラッシュします（Double Free問題）。
* **ディープコピー（安全）**:
コピー先のために完全に独立した新しいメモリ空間を確保し、そこに値を複製します。これにより、2つのオブジェクトは**完全に独立**します。ex02の `Array` クラスにおいて、コピーコンストラクタや代入演算子で `new T[n]` を行い、値を移し替えているのはこのためです。

### 5. `srand()` と `rand()` について

これらはC言語から引き継がれた、乱数（ランダムな数）を生成するための関数群です。

* **`rand()`**:
呼び出されるたびに、0から `RAND_MAX` までの間の適当な整数（疑似乱数）を返します。
* **`srand(unsigned int seed)`**:
`rand()` が乱数を作るための「種（シード）」を設定する関数です。
実はコンピュータは真のランダムを作れないため、計算式を使ってランダム「っぽい」数を出しています。シードを設定しないと、毎回全く同じ順番で乱数が出てしまいます。そのため、`srand(time(NULL))` のように「現在時刻」をシードとして渡すことで、プログラムを実行するたびに違う乱数が出るようにしています。

### 6. テスト4において、`numbers[MAX_VAL]` が最大値以上のインデックスをテストできている理由

C++（およびC言語）の配列は、**インデックス（添字）が「0」から始まります。**

* 要素数 `MAX_VAL` 個の配列を作った場合、使えるインデックスは **`0` から `MAX_VAL - 1**` までとなります。
* 例えば、`MAX_VAL` が `750` だとすると、アクセスできるのは `0` から `749` までです。
* したがって、`numbers[MAX_VAL]`（つまり `numbers[750]`）にアクセスしようとすると、それは配列の最後の要素の「1つ隣（範囲外）」を指すことになり、確実に Out of Bounds（範囲外アクセス）のテストになります。

### 7. テスト5において、`int`, `std::string` 以外にも使用できるか？

`Array` クラスは `template <typename T>` として設計されているため、型 `T` にはあらゆる型を指定できます。

* `float` や `double` などの他の組み込み型。
* `Bureaucrat` や `Form` といった自作のクラス型。
* ポインタ型（例: `int*`）など。

ただし、格納する型 `T` は、`Array` クラスの中で使用されている操作（引数なしのデフォルトコンストラクタ呼び出し `new T()` や、代入演算子 `=`）をサポートしている必要があります。

### 1. `srand()` と「現在時刻をシードとする」ことについて

**Q. `srand` で `time` をシードとするのは決まっていることですか？**
**A. 絶対のルールではありませんが、C/C++98において「毎回異なる乱数」を得るための最も一般的な定石（ベストプラクティス）です。**

**「シード（種）」と「現在時刻」の仕組み**
コンピュータは、完全にランダムな数（真の乱数）を作り出すことができません。その代わり、複雑な計算式を使って「ランダムに見える数列（疑似乱数）」を生成します。`rand()` がこの計算を行い、`srand()` はその計算の「開始地点（シード）」を設定する関数です。

* **固定の数を入れた場合（例: `srand(1)`）**:
開始地点が毎回同じになるため、プログラムを実行するたびに**全く同じ順番**で乱数が出現します（例: 毎回 42, 105, 8, ... のように出る）。これはテストやデバッグ時には結果が予測できて便利ですが、ゲームなどで予測不可能な動きをさせたい場合には適していません。
* **現在時刻を入れた場合（例: `srand(time(NULL))`）**:
`time(NULL)` は「1970年1月1日からの経過秒数」を返します。つまり、プログラムを実行するたびに1秒単位で異なる数値（開始地点）が `srand()` に渡されます。これにより、**実行するたびに異なるパターンの乱数**を生成することができます。

### 2. 組み込み型の初期化と `()` について

**Q. 逆に組み込み型って、0に初期化されないのですか？**
**A. はい、初期化されません。C++では、明示的に初期化しない限り「ゴミの値（メモリに元々残っていたデタラメなデータ）」が入ります。**

クラス（自作の型）の場合は、デフォルトコンストラクタが自動的に呼ばれて変数が初期化されます。しかし、`int` や `float` などの「組み込み型」は、処理速度を優先するため、勝手に初期化を行いません。

```cpp
int a;            // ゴミの値が入る（例: 32767 や -103984 など）
int* p = new int; // 確保されたメモリの中身はゴミの値

```

**Q. 末尾に `()` をつけると、どうして組み込み型であっても確実に 0 で初期化されるのですか？**
**A. C++の言語仕様として、`()` をつけると「値初期化（Value-initialization）」という特別な処理が走るようにルールが定められているからです。**

組み込み型に対して値初期化が行われると、C++のコンパイラはそれを「ゼロ初期化（Zero-initialization）」として解釈し、確実に `0`（ポインタなら `NULL`、floatなら `0.0f`）をセットしてくれます。Subjectのヒントに `int * a = new int();` を試すよう書かれているのは、このC++特有の安全な初期化機能を活用させるためです。

**Q. `n = 0` みたいに書くのはダメ？**
**A. 単一の変数であれば `new int(0)` と書くのは全く問題ありません。しかし、配列の場合は `()` を使うしかありません。**

* **1つの `int` を作る場合**:
`int* p = new int(0);` （明示的に0を代入。これも正解です）
`int* p = new int();`  （値初期化によって0になる。これも正解です）
* **配列（複数）を作る場合（重要）**:
`int* p = new int[5](0);` **（※これはコンパイルエラーになります）**
配列を動的確保する際、特定の値を指定して一括初期化する構文はC++98にはありません。しかし、`()` を使えば解決します。
`int* p = new int[5]();` （配列の5つすべての要素が `0` で初期化される）

今回作成する `Array` クラスは `new T[n]` のように配列を動的確保します。もし `T` が `int` だった場合、`new int[n]` では中身がゴミの値になりますが、`new int[n]()` と記述することで、配列全体を安全に `0` で初期化できるという強力なメリットがあります。
